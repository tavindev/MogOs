# Phase 3: User Space

Goal: isolated programs at EL0 on a small, capability-based native ABI.

## Steps

Clean-boot e2e tests assert no `panic:` line; a faulting process never takes the kernel down.

| # | Step | Done when |
| --- | --- | --- |
| 11 | Address spaces + EL0 + first syscall | 4 KiB pages; each process has an ASID-tagged TTBR0 table (ASID = process slot, at most 255 processes) holding the kernel's EL1-only identity blocks plus user mappings at 4 GiB and above (no higher-half kernel until Linux compatibility needs it). A user program (hand-written asm blob; no user Rust crate until step 14) calls `svc` and gets a result. With the timer on, process B reading A's address is terminated: the kernel prints `fault: <proc>`, A keeps printing, no `panic:`. Syscall round-trip benchmark recorded. |
| 12 | Handle table + rights | Each process reaches kernel objects only through its handle table; handles carry rights (read, write, map, duplicate, transfer, exec, wait, kill) and a generation, so a closed handle never reaches a recycled object. init starts with: console (write, duplicate), itself (kill); the boot-archive directory handle arrives with step 14's archive. e2e: writing to the console succeeds; a duplicate without write fails with a named error; a closed handle fails; a stale handle value fails after its entry is reused. |
| 13 | Memory budgets, no overcommit | Map allocates and zeroes frames immediately (no demand paging) and charges the process budget; so do the kernel objects it causes (page tables, kernel stack, pipe buffers; handle tables are fixed arrays in the scheduler slot). Over budget, the call fails. e2e: a program creating pipes or mapping memory in a loop gets an error and keeps running; no `panic:`. |
| 14 | Spawn from the boot archive | A cpio (newc) archive built on the host and bundled with `include_bytes!` holds static ELF programs (`PT_LOAD` only). `spawn(exe_handle, handles[])` takes an executable handle opened from a directory handle; passed handles are moved (the parent duplicates any it keeps); budget is moved from parent to child, so budgets never exceed RAM. e2e: a child using a handle value it was not given gets an error. |
| 15 | Completion I/O, pipes, blocking | I/O is submit/complete on handles; one `io_submit_wait` syscall covers the blocking case (libc `read`/`write` use it). Pipes are the first I/O object; `wait` returns exit status. Blocked tasks are not scheduled; with nothing runnable the CPU idles in `wfi`. e2e: the parent blocks on an empty pipe until the child writes. Pipe round-trip benchmark recorded. |
| 16 | Mutex + priority inheritance | Strict priorities, round-robin within a level. A mutex handle (`lock`/`unlock`, kernel tracks the owner) is shareable by handle transfer. e2e: L takes the mutex, H blocks on it, Mid spins forever at middle priority; the test powers off only from H after it acquires, which happens only with inheritance. |

## Native ABI rules

- Small: target 20-30 syscalls, each taking handles; no `ioctl`-style multiplexers; no global names (paths resolve from directory handles).
- Kernel objects live in fixed-capacity tables per type (index + generation); creation fails when a table is full. No `Box`/`Arc` for kernel objects: `Box::try_new`/`Arc::try_new` are unstable, and an aborting allocation would break the no-overcommit rule.
- Syscalls do bounded work: IRQs are masked in trap context, so the longest syscall bounds IRQ latency.

## Task context

- User FP/SIMD stays off (`CPACR_EL1.FPEN = 0`) until a test needs it: a user FP instruction traps and kills the process. When enabled (`FPEN = 0b11`, which also allows it at EL1; the kernel stays FP-free only because of the softfloat target), FP/SIMD registers are saved and restored on process switch, never on every trap.
- Syscall convention: `x8` = number, `x0`-`x5` = arguments, `x0` = result (negative = error), `svc #0`; matches what musl expects.
- `SP_EL0` and `TPIDR_EL0` (thread pointer for libc) are part of the context.

## What was done

Filled in as each step lands.

- Step 11a: the kernel's two 1 GiB blocks stay in a static boot table (EL1-only: UXN added to RAM, global) and are copied into each process's level-1 table; `arch::map_page` walks L1, L2, L3, taking missing tables from a fallible frame allocator, and `user_page` makes 4 KiB EL0 leaves (`nG`, PXN; code read-only and executable, stack read-write and UXN), with build-time asserts on every descriptor. A scheduler slot holds a frame and an address space: 0 is the boot table with ASID 0, otherwise the process's level-1 table with ASID = slot (`MAX_TASKS` 8, asserted at most 256). `task_switch` writes TTBR0 (+ `isb`, no TLB flush) and swaps SP_EL0 only when the space changes, so kernel-only switches pay nothing: SP_EL0 lives in the trap frame's spare slot, written by the switch, not by the vector asm (saving it on every trap cost about 2 ns of the 63 ns yield). hvf yield median 63/63 ns, boot 177/176 us (before/after, 21 interleaved).
- Step 11b: lower-EL AArch64 sync goes to the board: `svc` to `board_syscall` (`x8` number, `x0` result), any other EC to `board_user_fault`, which prints `fault: <slot>` and drops the process; lower-EL IRQ takes the timer preemption path. Two syscalls: `exit(code)` (code unused until `wait`) and `print(ptr, len)`; `kernel::syscall::decode` bounds the range to user VA (4 GiB to 512 GiB) and 4 KiB, then the board checks each page with `at s1e0r` and returns `EFAULT` (-14) for bad pointers; unknown numbers return `ENOSYS` (-38). On exit or kill TTBR0 moves to the next task before `tlbi aside1` flushes the dead ASID, so a reused slot starts clean. User programs are `global_asm!` blobs (`board/qemu-virt/src/user.s`) copied into a code page (I-cache synced) at their own address, with one stack page; SPSR EL0t, IRQs unmasked; each process takes 5 frames (3 tables, code, stack). `test=user`: process A checks that `print` rejects a kernel address and an unmapped user address, then prints `A: 0`..`A: 9` with a spin between lines; B, mapped one page higher, reads A's code address (absent in B's table; A's TLB entries carry another ASID) and is killed; boot idles until only it remains, then powers off. Passes under TCG and hvf.
- Step 11c: `CNTKCTL_EL1.EL0VCTEN` lets user code read `CNTVCT_EL0`/`CNTFRQ_EL0`. `test=bench-syscall` runs a process that times 100000 `print(sp, 0)` calls (a real syscall doing no I/O) and prints `syscall: <ns> ns/round-trip`, timer off. hvf median 27 ns (min 25), TCG 637 ns; yield 64/65 ns, boot 174/178 us vs before step 11 (within 5%; the 61 ns step-9 yield baseline re-measured at 63-64 today; [BENCHMARKS.md](../BENCHMARKS.md)).
- Step 11 security review: the kill line is `fault: <slot> ec=<EC> far=<FAR>` (arch passes ESR's class and FAR_EL1 to `board_user_fault`). `test=user` adds process C after B is killed: it takes B's slot and ASID (flushed by B's exit) at B's address and reads kernel RAM (`0x4000_0000`, EL1-only), so e2e asserts `fault: 2 ec=0x24 far=0x100000000` (B) and `fault: 2 ec=0x24 far=0x40000000` (C) exactly; dropping the flush does not change C's output under TCG or hvf, so the test exercises ASID reuse but cannot prove the flush. User programs get `USER_BASE` as a `global_asm!` const. `crates/kernel/tests/sched.rs` covers slot reuse, skipping a freed slot and `count`; the scheduler stores address spaces as `PhysAddr` (`PhysAddr(0)` = boot table). `enable_mmu` writes SCTLR_EL1 whole instead of OR-ing into the reset value: M, C, I, SA, SA0, SPAN, nTWI/nTWE (EL0 `wfi`/`wfe` allowed: EL0 cannot mask IRQs, so the next tick ends them) and the ARMv8.0 RES1 bits; UMA, DZE, UCT, UCI, E0E, EE are 0. `TPIDR_EL0` is part of the context: the trap frame grows to 288 bytes and `switch_el0_regs` swaps it with SP_EL0 on address-space switches only. `sync_icache` cleans the whole code page. `decode` takes `&[u64; 6]` (by value cost a 48-byte `memcpy` per syscall at opt-level 1, +2 ns). hvf medians, 21 interleaved vs `ce0e91a`: yield 65/64 ns, syscall 26/26 ns, boot 192/201 us (noise; an earlier set read 205/188).
- Step 12: `kernel::handle::Handles` is a fixed table of 16 entries per process, owned by the scheduler next to each slot's frame and address space (installed under the same IRQ mask as the task, cleared on exit). A handle value is `generation << 32 | index`; `close` bumps the entry's generation, so a closed value, or one whose entry was reused, is `EBADF`; lookup is an index plus a generation compare, no allocation. Rights are bits (read, write, map, duplicate, transfer, exec, wait, kill); only write (`write`) and duplicate (`dup`) are enforced so far. Objects: the console and a process (by slot). Every process the boot code spawns starts with init's set until spawn passes handles (step 14): handle 0 = console (write, duplicate), 1 = itself (kill); 0 is a valid handle value. Syscalls: `exit` 0, `write(handle, ptr, len)` 1 (replaces `print`, same pointer checks, returns `len`), `dup(handle, rights)` 2 (needs duplicate; rights must be a subset, else `EACCES`), `close(handle)` 3. Named errors are negated musl errno values in `kernel::syscall`: `EBADF` -9, `EACCES` -13, `EFAULT` -14, `EMFILE` -24 (table full), `ENOSYS` -38. `syscall::dispatch` resolves handles and runs `dup`/`close`, leaving the board only the console write and exit. `test=handles`: one process writes to the console, then through a duplicate without write (`EACCES`), a closed handle (`EBADF`), and the closed value after `dup` reused its entry (same index, new generation, checked in asm: `EBADF`), printing a line per result; e2e asserts the four lines exactly; passes under TCG and hvf. `crates/kernel/tests/handle.rs` covers generation reuse, a full table and the subset rule. hvf syscall median 27/28 and 26/27 ns (two sets of 21 interleaved vs `7089695`, +1 ns: the handle lookup and one more user instruction per call, under 5%). Deferred: `Object::Process` has no process generation, safe only because a self handle cannot outlive its table; kill, wait and transfer need slot + generation.
- Step 13: `mm::Budget` (limit, used) charges each frame at allocation time (`alloc`, `alloc_contiguous`; `None` with nothing charged over budget or out of frames; `free` refunds); `crates/mm/tests/budget.rs` covers physical exhaustion (the e2e covers the limit and the refund). The frame allocator moved from `kernel::run` into the board's one IRQs-masked static next to the scheduler (`Board::init_frames`, `free_frames`), so trap context can allocate and free. The scheduler keeps a `Memory` per slot (kernel stack base, budget, next map address) beside the handles; `exit` hands it back. Kernel stacks (16 KiB) now come from the frame allocator, not the heap: a process's is charged to its budget, a kernel task's is not. A process pays for everything it causes: level-1/2/3 tables, code and stack pages, kernel stack (9 frames fixed today); handle tables are fixed arrays inside the scheduler slot, so they are not charged; pipe buffers will be (step 15). Boot-spawned processes get a fixed budget of 25 frames until spawn moves budget from parent to child (step 14). Syscall `map(len)` 4: rounds `len` up to pages, allocates and zeroes them immediately (no demand paging) and maps them read-write, UXN, at the process's next map address (from the end of the stack's 2 MiB region, growing up); the kernel picks the address, so nothing overlaps, and musl's `mmap(NULL, ...)` (its malloc falls back from `brk` to `mmap`) builds on it. Over budget or out of frames it returns `ENOMEM` (-12); a zero `len`, or one over `MAX_MAP` (16 pages, 64 KiB), is `EINVAL` (-22). A request larger than the remaining budget fails up front; one that fails midway (a new table tipped it over) unmaps and refunds the pages it mapped and flushes the ASID; tables it added stay charged and are reused by the next map at the same address. Its IRQs-masked work (all the zeroing) is bounded by the `MAX_MAP` cap (16 pages and the few tables they need). `arch::free_space` walks a level-1 table and frees every user page, level-3 and level-2 table and the table itself; on exit or kill the board switches TTBR0 away, flushes the ASID, then frees the space and the kernel stack it is still running on (sound because nothing allocates before the trap returns). A spawn that fails midway frees the same way, so step 11's leaks are gone. `unmap` is deferred until a program needs it; it must check `end <= USER.end` itself, since nothing else bounds a caller-given range (map's own addresses stay low because `next` grows by at most the budget, which stays within RAM). `test=budget`: the program first maps its 16 remaining frames' worth of pages (needs 17 with the new level-3 table: `ENOMEM` after 15 pages, rolled back), then maps a page at a time, checking each reads zero and takes a write, until `ENOMEM`; it prints `M: ENOMEM after 15 pages` (25 - 9 fixed - 1 table; a rollback leak would lower it) and `M: still running`, then exits; the kernel prints free frames before and after its lifetime and e2e asserts they are equal (dropping the kernel-stack free or the rollback refund fails it). `test=budget`, `test=user` (C now reuses B's freed frames) and `test=handles` give the same lines under TCG and hvf. hvf medians, 21 interleaved vs `61b5108`: syscall 27/28 ns (+1 ns, the extra dispatch arm and state lookup, under 5%), yield 66/64 ns. Review: `Budget` and `Memory` are not `Copy`, so a ledger cannot be duplicated and double-charged; `Scheduler::exit` moves the slot's out with `mem::replace`. Step 14: spawn must tell out-of-memory apart from a full slot table (`spawn_user` returns `Full` for both today).
