# Phase 5: SMP, Threads and Fair Scheduling

Goal: several cores run threads of one process under a fair scheduler with resource groups. The locking model is fixed first, so every later shared table (page cache, network stack) is built on it. MogOs has no practical core cap (as many cores as QEMU `virt` offers: 512 under TCG, 64 under hvf) and no fixed object limits: an object is bounded by its owner's budget (Decided).

## Steps

Each done-when names its e2e test (a QEMU boot test in `crates/e2e/tests/boot.rs`; host unit tests only for tricky pure logic), the benchmarks it must hold and the ones it adds, and the invariants it keeps. Benchmarks are hvf medians of 21 interleaved boots against the step's base commit (`docs/BENCHMARKS.md`); "hold" means within noise, and a slowdown is a failure: removed, or shown unavoidable with numbers. The tracked kernel benchmarks are yield (`test=bench`, 70 ns), syscall (`test=bench-syscall`, 29 ns), pipe (`test=bench-pipe`, 374 ns) and boot (178 us without a disk); from step 25a they are measured at `-smp 1` and `-smp 4`, and from step 25c `test=bench-smp` adds throughput at 1, 2, 4, 8 and 12 cores. The e2e harness runs under TCG on a loaded host, so done-whens assert scheduler state and order, or a median of N samples under a loose ceiling, never a single wall-clock bound.

Step 25a (bring-up: `arch` boot, the secondary entry, per-core GIC and timer) runs in parallel with steps 26-27 (process/thread split and wait-on-address, one core). 25b (the scheduler per core) needs all three and rebases onto 26's process table; 25c (no core cap) follows 25b, and 28-32 follow in order.

| 24 | Lock model (one core) | `arch` provides the only lock and per-CPU primitives, all safe to call: `Lock<T>`, a ticket spinlock whose `lock()` saves DAIF and masks IRQs (the guard restores them) and whose `lock_masked()`, for trap hooks that are entered masked, skips the DAIF save; a waiter spins on `ldarh` of the owner ticket, no `wfe` until measured (hvf may trap it); `arch::cpu()`, the core index from TPIDR_EL1, set at boot; `PerCpu<T>`, one `T` per core, reached with IRQs masked. Why one lock: it is today's invariant ("touched only with IRQs masked on the one core") made cross-core, with no lock order inside the kernel state to get wrong; it is split only where step 32's counters show. The kernel crate gains no lock: `Scheduler`, `Pipes`, `Mutexes` and `Line` stay plain data, host-tested as before. Every trap hook takes `KERNEL` and returns still holding it; the trap exit releases it unconditionally, after `mov sp, x0`, through one board symbol, so no core resumes a task whose kernel stack another core still runs on. Keeps: `unsafe` only in `arch` and the board; `MAX_BUFFER`/`MAX_MAP` and the file syscalls' limits bound the work done under the lock as they bounded the work done masked; the IRQ path neither allocates nor prints. |

| 25b | Scheduler per core | Idle contexts are per core, not scheduler slots (no slot or ASID spent): `Scheduler` keeps `current` per core, in a `Vec` sized from `Board::cpus` at boot (never `MAX_CPUS`, so step 25c leaves it alone), `advance(cpu)` returns the highest-priority ready task not running elsewhere, or none, and the board then resumes that core's idle frame, which loads the boot table (`set_ttbr0(boot_table, 0)`), so no core keeps walking a dead process's tables. | 26 | Threads | Process state moves out of the per-slot arrays into a process table in `kernel` (`Processes<P>`: address space, `Handles`, `Memory` with the budget and map cursor, live thread count, generation); a task slot keeps its frame, state, priorities and kernel stack, and names its process. The ASID is the process index; index 0 is the kernel (boot table, ASID 0); the `<= 256` const assert moves to `MAX_PROCESSES`. New syscall `thread(entry, stack, tls, arg)` starts a thread in the caller's process at the caller's priority, its kernel stack charged to the process budget (the user stack is the caller's own mapped memory), and returns a thread handle (wait, kill, duplicate, transfer); `wait` on it is join and returns its exit code. New `thread_exit(code)` ends the calling thread, and the process ends with its last thread; `exit` (0) still ends the whole process (musl's `exit` and `exit_group`), and `Process` handles keep their meaning. Ending a process with threads on other cores marks and signals them; the last thread to leave a core does `flush_asid` and `free_space`, and the process index (its ASID) is freed only after that. A new thread's frame gets SP_EL0 = `stack` and TPIDR_EL0 = `tls`; `switch_el0_regs` now runs on every switch between user tasks (its "only when switching address spaces" premise no longer holds), and only the TTBR0 write is skipped when the next task shares the space. A sibling thread can rewrite user memory mid-syscall, so inputs the kernel parses (paths, spawn args, handle lists) are copied into a kernel buffer once, then validated; bulk data moves by raw copy, never through a `&[u8]` into live user memory; the `user_bytes` SAFETY rule is rewritten to match. e2e `test=threads` (one core): a process starts four threads that each add 1 to a shared counter 100000 times with an `ldxr`/`stxr` loop and `thread_exit` with their TPIDR_EL0; the main thread joins each (four distinct TLS values) and prints 400000; a process with one thread blocked on a pipe and one spinning is killed, both end, and `assert_no_leak` holds. Host tests: slot and process generations, last-thread exit, a zombie process. Benchmarks: yield, syscall, pipe, boot hold; new thread create + join round trip (ns), and yield between two threads of one process (no TTBR0 write; at most the cross-process yield). Keeps: handle values, generations and rights rules; a failed `spawn` or `thread` changes nothing; zombie and `reap` rules, now per process; one-level PI. |
| 27 | Wait-on-address with PI | New syscalls: `futex_wait(addr, expected, deadline)` blocks while the aligned `u32` at `addr` equals `expected` (read under the big lock, so a wake after a store is never lost; `deadline` in counter ticks, 0 for none, else `ETIMEDOUT`); `futex_wake(addr, n)` wakes up to `n` waiters, highest priority first, and returns the count; `futex_lock(addr)` / `futex_unlock(addr)` are the PI pair: the word holds the owner's thread id (0 when free; slot plus generation in the bits below the waiters bit, so an id never names a later thread), the uncontended path is a CAS in user space, and contended the kernel sets the waiters bit with an `arch` CAS on the user word (probed like `user_bytes_mut`), boosts the owner through `effective`, and `futex_unlock` hands the lock to the highest-priority waiter and `unboost`s; `EDEADLK` for the owner. The owner id must name a live thread of the caller's process, otherwise the caller takes the lock with `EOWNERDEAD`; each thread keeps a list of the PI words it owns with waiters, and its exit wakes them (so they get `EOWNERDEAD`). The key is (process, address): private only, since shared mappings arrive in phase 6. The wait table holds one entry per blocked task, so it is `MAX_TASKS` long and never full. A deadline is the kernel's only sleep: each core caches its earliest deadline and rearms its timer only when that moves earlier (a late fire just rechecks), so neither the switch path nor `yield` scans the table or writes the timer. `thread_exit` gains musl's clear-tid-and-wake (a tid address given to `thread`, zeroed and woken at exit) and a new `unmap` call frees pages (musl's detached threads unmap their own stack). Hard cutover: the kernel mutex object goes (syscalls 9-11, `Mutexes`, `Object::Mutex`, `Event::Lock`, `MAX_MUTEXES`; users `pi.rs`, `high.rs`, `low.rs` and the `crates/user` stubs), its numbers taken by the new calls; this removes cross-process locking until phase 6's shared mappings. Prerequisite: step 23 (musl). e2e: `test=pi` rewritten over `futex_lock` with threads of one process, same priorities and assertion (the owner outruns the middle-priority spinner); `test=futex`: four threads take a lock built on `futex_wait`/`futex_wake` around a plain counter, 100000 times each, and the total is exact; a 5 ms `futex_wait` returns `ETIMEDOUT` no earlier than its deadline (median of 11 under a loose ceiling); a forged owner id gets `EOWNERDEAD`; a C test over musl (`clone` with thread flags maps to `thread`, `futex` to these calls, `exit` to `thread_exit`, `exit_group` to `exit`) runs pthread mutex, condvar and join and prints its result. Host tests: the wait table (keys, wake order, deadlines). Benchmarks: yield, syscall, pipe, boot hold; new uncontended lock + unlock in user space (below the syscall round trip, which proves it makes no syscall), `futex_wake` with no waiter, and a wait/wake ping-pong between two threads (ns). Keeps: PI is one level (`unboost` doc); after an unlock that wakes a higher-priority task the caller switches at once if `outranked()`; user memory is reached only through the probing helpers; no ambient authority (a PI boost reaches only the caller's own threads). |
| 28 | Per-CPU run queues, wake preemption | Each core gets its own run queue: one index list per priority level, linked through the task table (no heap), so `advance` costs the number of levels, not a scan of every slot; blocked tasks hang on per-event lists, so `wake(event)` touches only its waiters; free slots are a free list. Placement is deterministic, with no heuristics: a woken task goes to the core it last ran on; if that core runs an equal or higher priority and another core idles, to the lowest-numbered idle core (an idle bitmap, one bit per core, sized at boot and scanned a word at a time). A woken task that outranks its core's current task preempts it at once, locally by switching or remotely by the reschedule SGI (phase 3's "a wake does not preempt yet" ends here; 25b already wakes idle cores). An idle core pulls one task before `wfi`, from the lowest-numbered core in an overloaded bitmap (cores with a task waiting, scanned a word at a time), so a pull reads N/64 words, not every core's queue. Still one big lock; the queues get their own locks only if step 32 shows it. e2e `test=smp-sched` (`-smp 4`): four kernel spinners each keep one core for a second (each records every core it ran on: exactly one); a top-priority thread blocked on a pipe, with all four cores busy with low-priority spinners, is picked before its core's next tick (asserted from the scheduler's switch record, not wall time); `test=pi` passes with owner and waiter on different cores. Benchmarks: yield, syscall, pipe, boot hold at `-smp 1` and `-smp 4`; `test=bench-smp`; new `test=bench-wake`, cross-core wake latency from a pipe write on one core to the reader's return on another (ns, hvf median). Keeps: the highest effective priority runs, round robin within a level (now per core); one-level PI; the boot context stays on core 0; the switch path does not allocate. |
| 29 | Fair class (EEVDF) | Levels 1-3 stay the strict-priority RT class with PI; level 0 becomes the fair class, scheduled per core by EEVDF: each task has a weight (1024 by default) and a virtual runtime; a task is eligible when its lag is not negative, and the eligible task with the earliest virtual deadline (vruntime + slice * 1024 / weight) runs. Vruntimes are kept relative to the queue's minimum vruntime, so the weighted average cannot overflow. Runtime is charged from `CNTVCT_EL0` at each switch and tick; a sleeper keeps its lag, clamped to one slice; a pulled task keeps its lag against the new core's virtual time; `yield` moves the task's deadline one slice on, so two yielding tasks still alternate (`test=yield`). One base slice constant (about 3 ms), no tunables; the slice end joins step 27's cached earliest event, and the timer is rearmed only when that moves earlier (a yield's new slice end is always later, so yield pays nothing). The pick is a linear scan of the core's fair tasks (bounded by `MAX_TASKS`; an indexed heap only if a benchmark asks). RT always beats fair, and PI lifts a fair owner to its waiter's RT level. Boot-spawned programs keep the top RT level (the tests rely on it) except the shell init (`msh`, busybox), which starts fair, so typed commands share the CPU fairly. e2e `test=fair` (`-smp 1`, or the hogs just take separate cores): two kernel hogs at weights 2048 and 1024 split one second 2:1 within 5% (from the scheduler's runtime accounting); beside four hogs, a task waking every 2 ms (`futex_wait` deadline) is picked at its wake while its lag stays within one slice plus the largest single charge; an RT task is picked at its wake ahead of the fair hogs (both asserted on scheduler state). Host tests: eligibility, deadline order, lag kept and clamped across sleep, lag kept across a pull, ties broken by slot, no overflow at 256 tasks of maximum weight. Benchmarks: yield, syscall, pipe, boot hold: `test=bench`'s kernel tasks (level 0) now run fair, so yield gates the fair pick, and syscall and pipe (top RT level) gate the RT path. Keeps: RT before fair; one-level PI; determinism (same inputs, same order). |
| 30 | Resource groups | A group is a kernel object reached by a handle (fixed table `Groups<G>`, entries by index and generation like pipes): a CPU weight (the group is one entity in each core's fair queue and its tasks share its time; groups do not nest), a CPU bandwidth (quota per period, a token bucket refilled each period; an overrun carries into the next period, so tokens can go negative and the long-run share holds; a group out of tokens has its fair tasks off the queues until the refill), and a task cap (live threads, counted at `spawn` and `thread`; over the cap is `EAGAIN`). Memory stays the per-process budgets, which already nest through `spawn`. New syscalls: `group(weight, quota_us, period_us, max_tasks)` creates one whose limits are no looser than the caller's group, `group_set` narrows or loosens within the same bound (write right); `spawn` takes an optional group handle (default: the caller's group), threads stay in their process's group, and boot processes start in the root group (no limits). RT tasks are capped by priority, not bandwidth. e2e `test=groups` (`-smp 1`): a hog in a group capped at 25% beside an uncapped hog gets 25% within 3% over a second (from the scheduler's accounting); groups weighted 2:1 holding one and three hogs split the CPU 2:1, not 1:3; a `thread` past the cap fails with `EAGAIN` and succeeds after a join; closing the last handle to a group frees it once its tasks have ended. Host tests: the token bucket with carried overrun, and the group entity in the fair pick. Benchmarks: yield, syscall, pipe, boot hold (group accounting rides the fair switch path); none new. Keeps: no ambient authority (a group only through its handle, limits only within the creator's); budgets unchanged; RT before fair. |
| 31 | No fixed limits | Approved by the user (Decided). No fixed system-wide object tables and no arbitrary per-process caps: the limit on any object is its owner's budget, and no overcommit stays (the next object fails with `ENOMEM` or its named error, never a panic); lookups stay O(1) by index and generation. **Per-process tables** grow in frames charged to the process: the handle table (`MAX_HANDLES` 16 goes) is a contiguous frame run that doubles when full (copied once per doubling), so a lookup stays a bounds check and one load; threads are bounded by the budget (each pins a kernel stack) and step 30's group task cap. **System tables** (tasks, processes, pipes, the wait table, groups) are reserved at boot from RAM, each as long as RAM could back objects of its kind (tasks: RAM / `TASK_STACK_FRAMES` frames, as each pins a kernel stack; pipes: RAM / one page; processes, groups and the wait table: tasks, processes also within the ASIDs); their share of RAM at `-m 128M` and `-m 1G` is written in the board's CLAUDE.md. Slots initialize lazily behind a high-water mark with a free list, so boot zeroes nothing and `.data` and `.bss` do not grow (`KERNEL` stays in `.data` for `Fs::new`; the tables are outside it). `MAX_TASKS` 8 and `MAX_PIPES` 16 go; `MAX_MUTEXES` left with step 27. `Scheduler::end`'s `holds` scan over every handle table becomes a per-process count of outstanding `Process` handles. **ASID**: 16-bit (`TCR_EL1.AS`) when `ID_AA64MMFR0_EL1.ASIDBits` says so, read at boot (cortex-a72 has 16), else 8; the switch path is unchanged (the ASID sits in TTBR0 bits 48-63 either way), so live processes cap at 65535 (or 255), a named cap until ASID rollover (Linux's generations) is needed. **RAM** from the DTB's memory node: the frame bitmap (`FRAME_WORDS`, a 128 MiB cap, goes) is sized at boot and placed after the image, and the boot table maps every GiB of RAM below `USER_BASE` (GiB 1-3: 3 GiB is a named cap until phase 6 maps all RAM). **Budgets** from RAM: the boot-spawned root (the shell init) gets every frame left after boot instead of `SHELL_BUDGET` (8 MiB); fixtures that test exhaustion keep exact small budgets, named in their tests. libc's fixed child budget (`CHILD_BUDGET` 1024 frames, halved down to `MIN_BUDGET`) becomes a rule over the parent's remaining budget (open: Notes). **I/O and memory calls**: `MAX_BUFFER` (4 KiB per read or write) and `MAX_MAP` (64 KiB) go: a call of any length runs in chunks of `CHUNK` (64 KiB, the bound on one trap's hold of `KERNEL`); after each chunk the call rewinds its `svc` (`TrapFrame::restart`) with buffer and length advanced and the count so far in its task slot, so the trap exit releases the lock and takes pending IRQs between chunks, and the caller sees one call. Pipe writes up to `PIPE_BUF` (4096) stay atomic. **Pipes**: `pipe(capacity)` sets the buffer at creation (pages charged to the creator, default one page), with no resize path. **Paths and lines**: `PATH_MAX` 4096 in the kernel, msh and libc (`PATH` 256 goes); `MAX_DEPTH` (16 components, which bounds a walk's block reads under the lock) goes, and a walk resumes like I/O every 16 components, so a 2048-component path holds the lock no longer per trap than today's longest walk; console `LINE` 256 becomes 4096 (Linux's N_TTY buffer). **Spawn**: `MAX_ARGS` 32 and the 4 KiB argument cap go; arguments are copied once (step 26) into pages charged to the child, its stack top, bounded by the budget. **libc**: `FILES` and `FDS` 32 and `CHILDREN` 8 grow on libc's heap, bounded by the handle table and the budget. **Runners**: the runners and the e2e harness boot `-m 1G` (boot is also tracked there, beside `-m 128M`). | 32 | Locks that scale | Approved by the user (Decided). A ticket lock's release is seen by every waiter: all of them spin on the owner word's line, so each hand-off costs a coherence transfer to each waiter and throughput collapses as cores grow. It is replaced by a queued lock (Linux's qspinlock without the pending bit): a 32-bit word with a locked byte and a tail (core index + 1 and nesting level). Uncontended, acquire is one CAS of 0 to locked and release one `stlrb` of 0, the same exclusive pair and store as the ticket lock; contended, a waiter swaps itself into the tail, links into its predecessor's MCS node and spins on its own node's line, and only the queue's head spins on the lock word. Nodes live in the per-CPU area, one per nesting level: two, since locks nest at most `KERNEL` then a leaf (`HEAP` or `CONSOLE`) and a `Lock` is only held masked, so no IRQ nests a third. FIFO and bounded waits as before; spinning with `sevl`/`wfe` on the node is measured against plain spinning under hvf, which may trap `wfe` (step 24's open point). The swap lands only if `bench-lock`'s uncontended round trip holds (2.9 ns) and `bench-smp` improves at 8 and 12 cores; otherwise the numbers are recorded and the ticket lock stays. Then the big lock is split where `bench-smp`'s contention counts blame it, if k workers reach less than 0.75k times one worker: expected order the run queues (per-core locks), then pipes, then the file system (whose `sync` holds the big lock across its flushes), with the lock order written in the board's CLAUDE.md; otherwise one lock stays. No paravirtual lock: hvf offers no hypercall to yield to a preempted holder, so above the host's 12 cores any FIFO lock convoys, and those core counts are correctness runs. e2e: `test=bench-lock`'s exact count with every core contending at `-smp 64` and `-smp 128` (TCG; 512 in the ignored scenario); every earlier scenario. Benchmarks: yield, syscall, pipe, boot hold at `-smp 1` and `-smp 4`; `bench-lock` uncontended and contended (4 and 12 cores); `bench-smp` at 1, 2, 4, 8, 12 cores before and after each change. Keeps: one lock order, written down; `lock()` masks before acquiring; trap hooks return holding `KERNEL`. |

## Decided

- **No practical core cap** (approved by the user, 2026-10-07: "we need to support as many cores as possible"): steps 25b-25c, 28-30 (per-core run queues, the per-core fair pick and group accounting are the real scaling work) and 32. Each per-core cost takes its cheapest safe form: GICv3 only, a dense index from the DTB, per-CPU areas sized at boot behind TPIDR_EL1, tree bring-up, a queued lock. Measured on this host (Apple M4 Pro, 12 cores: 8 performance, 4 efficiency; QEMU 9.2.1), with `-cpu cortex-a72`:
  - QEMU `virt`: GICv2 takes at most 8 cores; GICv3 at most 512 (TCG).
  - hvf with GICv3: QEMU starts at most 64 vCPUs (`HV_NO_RESOURCES` at 65). A guest using the trapped ICC registers is unverified until step 25c's first test. `-cpu host` fails on this M4 (`host-arm-cpu.sme` not found), so `-cpu cortex-a72` stays.
  - So hvf benchmarks scale over 1-12 cores (more vCPUs than host cores are overcommitted), and 64, 128 and 512 cores are TCG correctness runs.
- **GICv2 is deleted** in 25c, not kept beside GICv3: QEMU `virt` is the only supported board. A board that needs it (the Raspberry Pi 4 and 5 use the GICv2 GIC-400) brings it back in phase 11, chosen by the DTB's compatible.
- **No fixed limits** (approved by the user, 2026-10-07): step 31. Any object's limit is its owner's budget; system tables are sized at boot from RAM and per-process tables grow in charged frames. The caps that stay, each named where it lives: the ASID (65535 live processes with 16-bit ASIDs, 255 with 8), RAM mapped up to 3 GiB until phase 6, QEMU's 512 cores, `PIPE_BUF` 4096 atomicity, and `CHUNK` (64 KiB) and 16 path components per hold of `KERNEL`.
- **Kernel stack guard pages wait for phase 6**: in the 1 GiB identity block a guard page means splitting the RAM block into page tables; phase 6's higher-half kernel maps stacks page by page anyway and gives task kernel stacks guards at the same time.

## Notes

- Kernel code still never preempts itself: a trap runs to completion under the big lock, so the bounded-work rules (`MAX_BUFFER`, `MAX_MAP`, the path and `readdir` limits; from step 31 `CHUNK` and the 16-component walk chunk) now also bound how long other cores wait. A `sync` holds the lock for its flushes (about 137 us); phase 7's async block path removes that, or step 32 splits the file system out.
- `Lock<T>` and `PerCpu<T>` live in `arch` because `UnsafeCell` access needs `unsafe`; the kernel crate stays lock-free data behind the board, so its host tests need no lock.
- AArch64 broadcasts inner-shareable TLB and icache maintenance in hardware, so the SGI exists only for waking and rescheduling cores (idle wake, kill, wake preemption), never for shootdown.
- What phase 6 needs from this model: the probe-then-access helpers (`at s1e0r/w`) return `EFAULT` on a page not yet present (demand paging) or copy-on-write (the futex CAS), so kernel user access becomes fault-in-and-retry (or an exception fixup); and a page-in must never run under `KERNEL`, or every core stalls for the disk.
- MogFS v1's limits (`MAX_BLOCKS`, `MAX_INODES`, `MAX_FILE_SIZE`) and the virtio queue depth are phase 7's.
- Open for the user: libc's default child budget. Proposed: a `spawn` with budget 0 moves half of the caller's unused budget, so nesting halves and libc needs no query call; the alternative is a `budget` query syscall with libc choosing.
- Shared-memory futexes (keyed by frame), `wait_many`, an affinity API, scheduling domains, nested groups, signals and the exception channel are later phases.

## What was done

Filled in as each step lands.

- Step 24, lock model (one core): `arch::Lock<T>` (`src/aarch64/lock.rs`) is a ticket spinlock: `next.fetch_add` (an `ldxrh`/`stxrh` pair), then a spin on `ldarh` of `owner` (no `wfe`), release `stlrh` of `owner + 1`. `lock()` masks IRQs, then acquires, and its `Guard` releases, then restores DAIF; `lock_masked()` skips DAIF; `Guard::leak` keeps the lock held until the `unsafe` `Lock::unlock`. `arch::cpu()` reads TPIDR_EL1, which `boot.s` zeroes; `PerCpu<T>` is one `RefCell<T>` per core (`MAX_CPUS` = 4) reached through `with`, IRQs masked, reentry panics (nothing uses it yet). The board's `KERNEL` is `Lock<Kernel>`, `HEAP` and the new `CONSOLE: Lock<Uart>` are leaves (order `KERNEL`, then `HEAP` or `CONSOLE`); the `Global`/`KernelHeap` `UnsafeCell`s, their `unsafe impl Sync`s and every `KERNEL.0.get()` deref are gone, and the kernel crate gained no lock. Every trap hook takes `KERNEL` with `lock_masked` and returns holding it (`Guard::leak`); the trap exit calls the board's `board_unlock` right after `mov sp, x0`, once per trap. `board_irq` now switches through `switch` (it called `task_switch`, which would take the lock twice) and `task_exit` takes the `&mut Kernel` its hook holds. The `brk #0` self-test runs no hook, so `arch::breakpoint_self_test` is `unsafe` and the board takes `KERNEL` before it. Taking a lock is an exclusive RMW, which needs the MMU on, so `kernel::run` now calls `enable_mmu` before the hello line and the self-test (the lines print in the same order), and the board installs the DTB's PL011 into `CONSOLE` there. `Board::console` is a `Console` whose `write_fmt` holds `CONSOLE` for a whole line; panic, fault, echo and user `write` output stay on `UART0` unlocked, so a panic under the console lock still prints. No syscall fast path skips the lock: `dispatch` reads the caller's handle table on every call, including `bench-syscall`'s 0-byte write. e2e `lock_bench_reports_round_trips_and_an_exact_count` (`test=bench-lock`, two new `Board` methods `lock_round_trips` and `add_locked`): both locks' uncontended round trips, then two kernel tasks under the timer each add 10^7 to a counter under the lock; the first to finish has seen the other's additions (the timer interleaved them) and the total is exactly 2 * 10^7; every existing scenario passes unchanged. Benchmarks (hvf, base `9462ef0`, 63 interleaved runs, order alternating, load 6 to 13; median/min before -> after): pre-declared delta, one uncontended ticket round trip per trap, `bench-lock`'s 2.9 ns (min 2.8); yield 70/65 -> 70/67 ns, syscall 30/28 -> 32/29 ns, pipe 375/365 -> 389/378 ns (six traps per round trip, so about six lock round trips), boot 197/181 -> 208/182 us, rerun 195/179 -> 200/175 us (an A/A run of one kernel spread 6 us, so boot holds). Test-and-set (`swap(true, Acquire)`, `store(false, Release)`) costs 6.1 ns (min 6.0) under hvf against the ticket lock's 2.9, so no faster safe form replaces the ticket lock (TCG, informational: 4.3 against 7.1).
- Step 25a, SMP bring-up: `kmain` now turns on the MMU itself, first (`Board::enable_mmu` is gone from the kernel's port, so the boot table exists before any core starts), and reads the core count from the DTB (`Dtb::cpus`, the `/cpus` children whose `device_type` is `cpu`, at most `MAX_CPUS`).
