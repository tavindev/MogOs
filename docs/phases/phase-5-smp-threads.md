# Phase 5: SMP, Threads and Fair Scheduling

Goal: several cores run threads of one process under a fair scheduler with resource groups. The locking model is fixed first, so every later shared table (page cache, network stack) is built on it.

## Steps

Each done-when names its e2e test (a QEMU boot test in `crates/e2e/tests/boot.rs`; host unit tests only for tricky pure logic), the benchmarks it must hold and the ones it adds, and the invariants it keeps. Benchmarks are hvf medians of 21 interleaved boots against the step's base commit (`docs/BENCHMARKS.md`); "hold" means within noise, and a slowdown is a failure: removed, or shown unavoidable with numbers. The tracked kernel benchmarks are yield (`test=bench`, 70 ns), syscall (`test=bench-syscall`, 29 ns), pipe (`test=bench-pipe`, 374 ns) and boot (178 us without a disk); from step 25 they are measured at `-smp 1` and `-smp 4`.

Step 25 runs in parallel with steps 26-27: 25 lives in `arch` boot, `kmain`, the GIC and the timer, 26-27 in the kernel's scheduler, handles and syscalls. Both touch `Scheduler` and the board's trap hooks, so 25 merges first and 26 rebases onto its per-CPU `current`. 28 needs both; 29-31 follow in order.

| 24 | Lock model (one core) | `arch` provides the only lock and per-CPU primitives, all safe to call: `Lock<T>`, a ticket spinlock whose `lock()` saves DAIF and masks IRQs (the guard restores them) and whose `lock_masked()`, for trap hooks that are entered masked, skips the DAIF save (one `ldaxr`/`stxr` loop to take a ticket, one `stlr` to release); `arch::cpu()`, the core index from TPIDR_EL1, set at boot; `PerCpu<T>`, one `T` per core, reached with IRQs masked. One big lock first: the board's `KERNEL` becomes `Lock<Kernel>`, `FS_DISK` and `HEAP` get their own (order `KERNEL`, `FS_DISK`, `HEAP`; the heap is a leaf), and the `unsafe impl Sync`s and `UnsafeCell` derefs go. Why one lock: it is today's invariant ("touched only with IRQs masked on the one core") made cross-core, with no lock order inside the kernel state to get wrong; it is split only where step 31's counters show. The kernel crate gains no lock: `Scheduler`, `Pipes`, `Mutexes` and `Line` stay plain data, host-tested as before. Two single-core rules are replaced now, before a second core can break them: a hook that switches tasks keeps the lock until the trap exit has moved `sp` to the next frame (`arch` releases it after `mov sp, x0`), so no core resumes a task whose kernel stack another core still runs on; and `task_exit` no longer frees the stack it runs on, but parks it in a per-CPU cell that the core's next trap frees. e2e: every existing scenario passes unchanged. Benchmarks: yield, syscall, pipe, boot hold; new `test=bench-lock`, uncontended `lock_masked` acquire + release (ns). Keeps: `unsafe` only in `arch` and the board; `MAX_BUFFER`/`MAX_MAP` and the file syscalls' limits bound the work done under the lock as they bounded the work done masked; the IRQ path neither allocates nor prints. |
| 25 | SMP bring-up | `kmain` starts the secondaries with PSCI `CPU_ON` (HVC, like `SYSTEM_OFF`; core count from the DTB, at most `MAX_CPUS` = 4) without waiting for them, so boot pays only the calls. Each secondary enters an `arch` entry point on its own 16 KiB boot stack (allocated before `CPU_ON`), sets TPIDR_EL1, installs the vectors, turns on the MMU with the boot table (ASID 0), enables its banked GICv2 CPU interface and timer PPI, and parks in its idle context. Idle contexts are per CPU, not scheduler slots (no slot or ASID spent): `Scheduler` keeps `current` per CPU, `advance(cpu)` returns the highest-priority ready task not running elsewhere, or none, and the board then resumes that core's idle frame (`wfi`); the boot context stays slot 0, pinned to CPU 0; one run queue under the big lock for now. One SGI, "reschedule" (`GICD_SGIR`): `kill` of a task running on another core marks it and signals that core, which ends it at the trap. TLB and icache maintenance move to the inner-shareable forms the hardware broadcasts to every core (`flush_asid` uses `tlbi aside1is`, `invalidate_icache` uses `ic ialluis`, each with `dsb ish`): AArch64 needs no IPI for TLB shootdown. The cargo runners and the e2e harness boot `-smp 4` from here, and AGENTS.md's target line changes with them. e2e `test=smp`: each core prints `cpu <n>: online`; with the timer off, four kernel tasks each increment a shared atomic and spin until it reads 4 (on fewer cores this never ends), then print their core: four distinct ones; each core then takes timer ticks; a process spinning on another core is killed and every frame comes back (`assert_no_leak`). All earlier scenarios pass at `-smp 4`. Benchmarks: yield, syscall, pipe, boot hold at `-smp 1` and `-smp 4`; `test=bench-lock` adds contended acquire + release (four cores on one lock, ns per acquisition), and checks that a counter incremented under the lock is exact. Keeps: slot 0 never exits; every frame is charged to a budget; step 24's switch and stack-free rules. |
| 26 | Threads | Process state moves out of the per-slot arrays into a process table in `kernel` (`Processes<P>`: address space, `Handles`, `Memory` with the budget and map cursor, live thread count, generation); a task slot keeps its frame, state, priorities and kernel stack, and names its process. The ASID is the process index (the `<= 256` const assert moves to `MAX_PROCESSES`). New syscall `thread(entry, stack, tls, arg)` starts a thread in the caller's process at the caller's priority, its kernel stack charged to the process budget (the user stack is the caller's own mapped memory), and returns a thread handle (wait, kill, duplicate, transfer); `wait` on it is join and returns its exit code. New `thread_exit(code)` ends the calling thread, and the process ends with its last thread; `exit` (0) still ends the whole process (musl's `exit` and `exit_group`), and `Process` handles keep their meaning. A new thread's frame gets SP_EL0 = `stack` and TPIDR_EL0 = `tls`; `switch_el0_regs` now runs on every switch between user tasks (its "only when switching address spaces" premise no longer holds), and only the TTBR0 write is skipped when the next task shares the space. e2e `test=threads`: a process starts four threads that each add 1 to a shared counter 100000 times with an `ldxr`/`stxr` loop and `thread_exit` with their TPIDR_EL0; the main thread joins each (four distinct TLS values) and prints 400000; a second process with one thread blocked on a pipe and one spinning is killed, both end, and `assert_no_leak` holds. Host tests: slot and process generations, last-thread exit, a zombie process. Benchmarks: yield, syscall, pipe, boot hold; new thread create + join round trip (ns), and yield between two threads of one process (no TTBR0 write; at most the cross-process yield). Keeps: handle values, generations and rights rules; a failed `spawn` or `thread` changes nothing; zombie and `reap` rules, now per process; one-level PI. |
| 27 | Wait-on-address with PI | New syscalls: `futex_wait(addr, expected, deadline)` blocks while the aligned `u32` at `addr` equals `expected` (read under the big lock, so a wake after a store is never lost; `deadline` in counter ticks, 0 for none, else `ETIMEDOUT`); `futex_wake(addr, n)` wakes up to `n` waiters, highest priority first, and returns the count; `futex_lock(addr)` / `futex_unlock(addr)` are the PI pair: the word holds the owner's thread id (0 when free), the uncontended path is a CAS in user space, and contended the kernel sets a waiters bit with an `arch` CAS on the user word (probed like `user_bytes_mut`), boosts the owner through `effective`, and `futex_unlock` hands the lock to the highest-priority waiter and `unboost`s; `EDEADLK` for the owner, and a waiter whose owner has exited takes the lock with `EOWNERDEAD`. The key is (process, address): private only, since shared mappings arrive in phase 6. The wait table holds one entry per blocked task, so it is `MAX_TASKS` long and never full. A deadline is the kernel's only sleep: each core's timer is armed for the earlier of its next tick and its earliest deadline. Hard cutover: the kernel mutex object goes (syscalls 9-11, `Mutexes`, `Object::Mutex`, `Event::Lock`, `MAX_MUTEXES`), its numbers taken by the new calls; step 23's dispatcher and `crates/user`'s stubs move with it. e2e: `test=pi` rewritten over `futex_lock` with threads of one process, same priorities and assertion (the owner outruns the middle-priority spinner); `test=futex`: four threads take a lock built on `futex_wait`/`futex_wake` around a plain counter, 100000 times each, and the total is exact, and a 5 ms `futex_wait` returns `ETIMEDOUT` no earlier than its deadline and before the next 10 ms tick; a C test over musl (`clone` with thread flags maps to `thread`, `futex` to these calls, `exit` to `thread_exit`, `exit_group` to `exit`) runs pthread mutex, condvar and join and prints its result. Host tests: the wait table (keys, wake order, deadlines). Benchmarks: yield, syscall, pipe, boot hold; new uncontended lock + unlock in user space (below the syscall round trip, which proves it makes no syscall), `futex_wake` with no waiter, and a wait/wake ping-pong between two threads (ns). Keeps: PI is one level (`unboost` doc); after an unlock that wakes a higher-priority task the caller switches at once if `outranked()`; user memory is reached only through the probing helpers. |
| 28 | Per-CPU run queues, wake preemption | Each core gets its own run queue: one index list per priority level, linked through the task table (no heap), so `advance` costs the number of levels, not a scan of every slot; blocked tasks hang on per-event lists, so `wake(event)` touches only its waiters; free slots are a free list. Placement is deterministic, with no heuristics: a woken task goes to the core it last ran on; if that core runs an equal or higher priority and another core idles, to the lowest-numbered idle core. A woken task that outranks its core's current task preempts it at once, locally by switching or remotely by the reschedule SGI (phase 3's "a wake does not preempt yet" ends here). An idle core pulls one task from the longest queue before `wfi`. Still one big lock; the queues get their own locks only if step 31 shows it. e2e `test=smp-sched` (`-smp 4`): four kernel spinners each keep one core for a second (each records every core it ran on: exactly one); a top-priority thread blocked on a pipe, with all four cores busy with low-priority spinners, runs within 1 ms of the write (stamped with `CNTVCT_EL0`, readable at EL0; the tick is 10 ms); `test=pi` passes with owner and waiter on different cores. Benchmarks: yield, syscall, pipe, boot hold at `-smp 1` and `-smp 4`; new `test=bench-wake`, cross-core wake latency from a pipe write on one core to the reader's return on another (ns). Keeps: the highest effective priority runs, round robin within a level (now per core); one-level PI; the boot context stays on core 0; the switch path does not allocate. |
| 29 | Fair class (EEVDF) | Levels 1-3 stay the strict-priority RT class with PI; level 0 becomes the fair class, scheduled per core by EEVDF: each task has a weight (1024 by default) and a virtual runtime; a task is eligible when its lag is not negative, and the eligible task with the earliest virtual deadline (vruntime + slice * 1024 / weight) runs. Runtime is charged from `CNTVCT_EL0` at each switch and tick; a sleeper keeps its lag, clamped to one slice; a pulled task keeps its lag against the new core's virtual time; `yield` moves the task's deadline one slice on, so two yielding tasks still alternate (`test=yield`). One base slice constant (about 3 ms), no tunables; the core's timer is armed for the earliest of the fair task's slice end, the RT tick and the earliest deadline. The pick is a linear scan of the core's fair tasks (bounded by `MAX_TASKS`; an indexed heap only if a benchmark asks). RT always beats fair, and PI lifts a fair owner to its waiter's RT level. Boot-spawned programs keep the top RT level (the tests rely on it) except the shell init (`msh`, busybox), which starts fair, so typed commands share the CPU fairly. e2e `test=fair` (`-smp 1`, or the hogs just take separate cores): two kernel hogs at weights 2048 and 1024 split one second 2:1 within 5% (from the scheduler's runtime accounting); a task waking every 2 ms (`futex_wait` deadline) beside four hogs never waits longer than one base slice; an RT task preempts the fair hogs at once. Host tests: eligibility, deadline order, lag kept and clamped across sleep, lag kept across a pull, ties broken by slot. Benchmarks: yield, syscall, pipe, boot hold: `test=bench`'s kernel tasks (level 0) now run fair, so yield gates the fair pick, and syscall and pipe (top RT level) gate the RT path. Keeps: RT before fair; one-level PI; determinism (same inputs, same order). |
| 30 | Resource groups | A group is a kernel object reached by a handle (fixed table `Groups<G>`, entries by index and generation like pipes): a CPU weight (the group is one entity in each core's fair queue and its tasks share its time; groups do not nest), a CPU bandwidth (quota per period, a token bucket refilled each period; a group out of tokens has its fair tasks off the queues until the refill), and a task cap (live threads, counted at `spawn` and `thread`; over the cap is `EAGAIN`). Memory stays the per-process budgets, which already nest through `spawn`. New syscalls: `group(weight, quota_us, period_us, max_tasks)` creates one whose limits are no looser than the caller's group, `group_set` narrows or loosens within the same bound (write right); `spawn` takes an optional group handle (default: the caller's group), threads stay in their process's group, and boot processes start in the root group (no limits). RT tasks are capped by priority, not bandwidth. e2e `test=groups` (`-smp 1`): a hog in a group capped at 25% beside an uncapped hog gets 25% within 3% over a second; groups weighted 2:1 holding one and three hogs split the CPU 2:1, not 1:3; a `thread` past the cap fails with `EAGAIN` and succeeds after a join; closing the last handle to a group frees it once its tasks have ended. Host tests: the token bucket and the group entity in the fair pick. Benchmarks: yield, syscall, pipe, boot hold (group accounting rides the fair switch path); none new. Keeps: no ambient authority (a group only through its handle, limits only within the creator's); budgets unchanged; RT before fair. |
| 31 | Tables sized for SMP, lock split by measurement | Fixed tables grow, still fixed and fallible (the next object fails with its error, never a panic): tasks 8 to 256, processes 64 (ASIDs stay 8-bit), pipes 16 to 128, handles 16 to 64 per process, groups 16, the wait table equal to tasks; the sizes and the kernel memory they cost are written in the board's CLAUDE.md. The tables stay zero-initialized, outside `.data` (`KERNEL` is in `.data` because `Fs::new` builds a non-zero file system, so the tables move out of it or the file system does), so the image and boot do not grow. Step 28's lists removed every hot-path scan of a table; any linear scan left is on a cold path (create, mount) and named. Each `Lock` counts contended acquisitions per core. `test=bench-smp` runs one, two and four pipe pairs at `-smp 4`, reports aggregate round trips per second and the contention counts; if four pairs reach less than 3x one pair and the counters blame the big lock, the hottest state moves to its own lock (expected order: the run queues, then pipes, then the file system, whose `sync` holds the big lock across its flushes), with the lock order written in the board's CLAUDE.md; otherwise the numbers are recorded and one lock stays. e2e `test=limits`: threads, processes, pipes, handles and groups are created up to each cap, the next fails with its named error, and freeing one lets it succeed; all earlier scenarios pass. Benchmarks: yield, syscall, pipe, boot hold at the new sizes, `-smp 1` and `-smp 4`; new `test=bench-smp` scaling and contention counts. Keeps: a process index is its ASID (at most 255); `MAX_BUFFER`/`MAX_MAP` bound work under the lock; no overcommit. |

## Notes

- Kernel code still never preempts itself: a trap runs to completion under the big lock, so the bounded-work rules (`MAX_BUFFER`, `MAX_MAP`, the path and `readdir` limits) now also bound how long other cores wait. A `sync` holds the lock for its flushes (about 137 us); phase 7's async block path removes that, or step 31 splits the file system out.
- `Lock<T>` and `PerCpu<T>` live in `arch` because `UnsafeCell` access needs `unsafe`; the kernel crate stays lock-free data behind the board, so its host tests need no lock.
- AArch64 broadcasts inner-shareable TLB and icache maintenance in hardware, so the SGI exists only for rescheduling (kill, wake preemption), never for shootdown.
- Shared-memory futexes (keyed by frame), `wait_many`, an affinity API, scheduling domains, nested groups, signals and the exception channel are later phases.
