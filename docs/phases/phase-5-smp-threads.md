# Phase 5: SMP, Threads and Fair Scheduling

Goal: several cores run threads of one process under a fair scheduler with resource groups. The locking model is fixed first, so every later shared table (page cache, network stack) is built on it. MogOs has no practical core cap (as many cores as QEMU `virt` offers: 512 under TCG, 64 under hvf) and no fixed object limits: an object is bounded by its owner's budget (Decided).

## Steps

Each done-when names its e2e test (a QEMU boot test in `crates/e2e/tests/boot.rs`; host unit tests only for tricky pure logic), the benchmarks it must hold and the ones it adds, and the invariants it keeps. Benchmarks are hvf medians of 21 interleaved boots against the step's base commit (`docs/BENCHMARKS.md`); "hold" means within noise, and a slowdown is a failure: removed, or shown unavoidable with numbers. The tracked kernel benchmarks are yield (`test=bench`, 70 ns), syscall (`test=bench-syscall`, 29 ns), pipe (`test=bench-pipe`, 374 ns) and boot (178 us without a disk); from step 25a they are measured at `-smp 1` and `-smp 4`, and from step 25c `test=bench-smp` adds throughput at 1, 2, 4, 8 and 12 cores. The e2e harness runs under TCG on a loaded host, so done-whens assert scheduler state and order, or a median of N samples under a loose ceiling, never a single wall-clock bound.

Step 25a (bring-up: `arch` boot, the secondary entry, per-core GIC and timer) runs in parallel with steps 26-27 (process/thread split and wait-on-address, one core). 25b (the scheduler per core) needs all three and rebases onto 26's process table; 25c (no core cap) follows 25b. The big lock is split ahead of the scheduler work (Decided): 26a (per-process locks, a compile-time lock order) follows 26 and comes before 27, whose futex waiters are born under its process lock; then 27, 28 (per-core run queues each touched only by its own core, a wake inbox, per-pipe locks), 28a (a direct-switch call for ping-pong) and 29-32 in order.

| 26a | Per-process locks, lock-free handle lookups, compile-time lock order | Decided (below). A call that touches only its own process's state takes no global lock (a `map` takes only the frame allocator's, for one bitmap pass): today every syscall takes `KERNEL`, and `bench-smp` (25c) falls from 14.4 M 0-byte writes per second at one worker to 0.02 M at 12. **Per-process lock**: the handle table, the map cursor and (step 27) the futex waiters leave the scheduler's process table for a per-process `Process` (plain data in the kernel crate, which stays lock-free) that the board keeps in a `Lock` per process index, each on its own 128-byte line (the M4 host's line, `hw.cachelinesize`; A72's is 64, but the host's is the one that bounces). The table of these locks is reached without `KERNEL`, and an entry stays live while a thread of its process runs or its release is pending (below). Lifecycle (state, generation, live threads) stays with the scheduler; allocating and freeing a process index takes a process-table lock for that operation only. **The budget is atomic**, outside the process lock: limit and used, each a `u32` count of frames (16 TiB, a named cap), packed in one `AtomicU64`, and charge, refund, shrink and grow are each one CAS on the pair, so a check and its update never see two different limits; a charge over the limit fails with `ENOMEM`, changing nothing, and `shrink` returns false instead of asserting (`mm`'s `assert!` there, `crates/mm/src/lib.rs` 177-180, would otherwise be a panic a user can trigger once a sibling's charge lands between check and shrink). A thread's end, a pipe's free and `wait`'s refund reach any process's budget without its lock. A run of CASes is not atomic as a whole: `listen` charges each holder of the socket for its backlog one CAS at a time, so another holder's charge can briefly see `ENOMEM` that would have fit once the run is done (named, accepted). (Found in this review: releasing a `Process` handle during a kill credits the child's limit to the killer's budget, not the holder's, `trap.rs` 228-232; it is being fixed separately.) **Lock-free lookups** (chosen over eliding the lock for single-threaded processes, below): each handle-table entry is `AtomicU64` words behind its own 64-bit sequence word (no wrap), a seqlock: the table's writers (`dup`, `close`, `insert`, `spawn`'s split) hold the process lock, store the sequence odd (relaxed), `fence(Release)` (`dmb ishst`), store the words (relaxed), then store the sequence even with release; a lookup reads the sequence (acquire), the entry's words (relaxed), `fence(Acquire)` (`dmb ishld`), the sequence again, and retries on a change or an odd value, so it stores nothing and sibling threads' lookups share the line without bouncing it. An object reached by a lookup is rechecked once its own lock is held (the entry's sequence unchanged), so a sibling's `close` linearizes before or after the call, never during: a `Dir` or `Node` stays covered by its open count until the file-system call finishes, as `KERNEL` is held from the recheck on. `close` writes the table (the sequence bump) first, then drops the inode count under `KERNEL`, so a lookup that sees the entry finds the count still held. The ordering argument written here and in the code is the guarantee (Linux's `seqcount_t` read and write sides); `loom` is a dev-dependency only if a host test with it proves worth its cost. Safe atomics, so the kernel crate keeps `forbid(unsafe_code)`. Calls that touch only the calling thread (an unknown number, arguments rejected before a lookup) take no lock either. **Commit rule** (step 31's undo rule, brought forward): every table write comes after every step that can fail, so a failed call writes nothing a sibling's lookup could see; `spawn` removes the entries it moves from the parent last, after the child is complete, so a sibling never gets a spurious `EBADF` from a spawn that then fails. **Per-inode open count** (moved here from step 31): kept as handles to a `Dir` or `Node` open and close (and, from 31, as a suspended walk pins its inode), under `KERNEL` with the file system; `unlink` checks it, and `Scheduler::holds`, which scans every process's handles and would need every process lock, is deleted. **Order**: a process, then `KERNEL` (the scheduler, pipes, mutexes until 27, the console line, the file system; `NET` keeps its place after it), then the process table, then the frame allocator, then `CONSOLE`; `HEAP` is the only leaf by construction; written in the board's CLAUDE.md. No path holds two process locks: `spawn` holds the parent's lock throughout (its handle list leaves the parent's table atomically) and writes the unpublished child's entry through an `unsafe` board accessor (SAFETY: the index is allocated to this spawn and published only at its end, so no handle names it and no thread runs in it); `kill` and `wait` work under `KERNEL` and take no other process's lock. No step holds two locks of one level, so `lock_two` is not built (one that later must takes them in index order, and `lock_two(a, a)` takes one). **Ending**: the kill mark is set and read only under `KERNEL`, the lock the killer's "is it running" check holds (the killer marks a running thread and signals its core, whose IRQ path ends it), so no thread is judged not running and left running. Ending a thread is scheduler work and an atomic budget refund, with no process lock. A thread's kernel stack is never freed by the core running on it: the end parks it in a per-CPU slot, and the trap exit's board symbol, already called after `mov sp, x0` on the switching path, frees it there, in the same trap, once this core is off that stack (from 28 it also clears the on-core flag); since another core can now take frames without `KERNEL`, nothing is freed earlier. Releasing an ended process (its handles under its lock, then `flush_asid` and `free_space`) is the same deferred work in the same place, and its index (its ASID) is freed only after it; a trap that does not switch pays nothing. `wait` returns only after the child's frames are freed (the release marks the child reapable last), so a parent's refund never races its child's frames. The board's CLAUDE.md rule becomes: "A hook that switches takes `KERNEL` and returns holding it; the trap exit releases it after `mov sp, x0`. A frame is never freed by the core running on it: a thread's stack and an ended process's release are deferred per-CPU work the trap exit's board symbol runs after `mov sp, x0` in the same trap; a process index (its ASID) is freed only after `flush_asid` and `free_space`, and `wait` returns only after that." **Compile-time order** (Fuchsia netstack3's `lock_order`): a level is a marker type with `LockAfter<A>` implemented for every earlier level `A` (each edge spelled out, no transitive closure by blanket impl); `Lock<T, L>::lock` takes `&'a mut W<'_, P>` with `L: LockAfter<P>` and returns `(Guard<'a, T>, W<'a, L>)`: the guard borrows the parent witness for its whole life, and the child witness carries that lifetime, so it cannot outlive its guard. A trap hook's root witness comes from one `unsafe` constructor at its entry; `Board::console`, which the kernel crate calls holding no board lock, makes its own. Levels are types, not a const `LEVEL`, because stable Rust cannot bound one const generic below another (`generic_const_exprs` is nightly). `CONSOLE` takes a witness and hands none out (its guard borrows it), so nothing is taken under it; panic output writes `UART0` unlocked, as now. `HEAP`, reached through `GlobalAlloc`, takes none and takes nothing under it. ## Decided

- **No practical core cap** (approved by the user, 2026-10-07: "we need to support as many cores as possible"): steps 25b-25c, 28-30 (per-core run queues, the per-core fair pick and group accounting are the real scaling work) and 32. Each per-core cost takes its cheapest safe form: GICv3 only, a dense index from the DTB, per-CPU areas sized at boot behind TPIDR_EL1, tree bring-up, a queued lock. Measured on this host (Apple M4 Pro, 12 cores: 8 performance, 4 efficiency; QEMU 9.2.1), with `-cpu cortex-a72`:
  - QEMU `virt`: GICv2 takes at most 8 cores; GICv3 at most 512 (TCG).
  - hvf with GICv3: QEMU starts at most 64 vCPUs (`HV_NO_RESOURCES` at 65). A guest using the trapped ICC registers is unverified until step 25c's first test. `-cpu host` fails on this M4 (`host-arm-cpu.sme` not found), so `-cpu cortex-a72` stays.
  - So hvf benchmarks scale over 1-12 cores (more vCPUs than host cores are overcommitted), and 64, 128 and 512 cores are TCG correctness runs (user, 2026-10-07).
- **GICv2 is deleted** in 25c (user, 2026-10-07): GICv3 only, as QEMU `virt` is the only supported board. If phase 11 picks a Raspberry Pi (4 and 5 use the GICv2 GIC-400), the driver is restored from history then.
- **A child without an explicit budget charges its parent's group** (user, 2026-10-07; steps 30-31): like a cgroup, the group's frame budget is shared by its budget-0 processes, and an explicit budget still caps a child. libc spawns with budget 0.
- **No fixed limits** (approved by the user, 2026-10-07): step 31. Any object's limit is its owner's budget; system tables are sized at boot from RAM and per-process tables grow in charged frames. The caps that stay, each named where it lives: the ASID (65535 live processes with 16-bit ASIDs, 255 with 8), RAM mapped up to 3 GiB until phase 6, QEMU's 512 cores, `PIPE_BUF` 4096 atomicity, and `CHUNK` (64 KiB) and 16 path components per lock hold.
- **Kernel stack guard pages wait for phase 6** (user, 2026-10-07): in the 1 GiB identity block a guard page means splitting the RAM block into page tables; phase 6's higher-half kernel maps stacks page by page anyway and gives task kernel stacks guards at the same time.
- **The big lock is split ahead of the per-core scheduler** (coordinator, 2026-10-07, from 25c's `bench-smp` and the sources below, weighed against speed with complete safety, compile-time invariants and simplicity): steps 26a, 28 and 32, in that order, with 27 built on 26a and 29-31 on 28. 25c measured 0-byte writes at 14.4 M/s with one worker and 0.02 M/s with 12, every syscall taking `KERNEL`. Linux's big kernel lock went in with 2.0 (1996) and out with 2.6.39 (2011), about 15 years, because code kept being written under it; splitting before steps 27-31 add more state under `KERNEL` keeps that from starting here. The Scalable Commutativity Rule (Clements et al., SOSP 2013): operations that commute, like two processes' own syscalls, have implementations whose memory accesses do not conflict, so per-process state is the scalable form. Lock order checked at compile time: Fuchsia netstack3's `lock_order` crate (levels as types, zero-sized witnesses). The wake inbox is Linux's remote wake list (Zijlstra, 2011, "move the second half of ttwu() to the remote cpu"); the on-core flag is Linux's `p->on_cpu`, which `try_to_wake_up` waits on with `smp_cond_load_acquire`; the handle lookup's seqlock is Linux's `seqcount_t` read side (Lameter, 2005, for the time-of-day read path). For the pipe trap's second lock round trip (about +15 ns of 344, estimate), seqlock lookups were chosen over eliding the process lock for single-threaded processes: elision is a run-time check with `unsafe` in the board, needs an atomic thread count with ordered 1-to-2 and 2-to-1 transitions and every remote path to release before making a thread runnable, and helps only single-threaded processes, while seqlock reads cover every process with safe atomics, store nothing, and cost an estimated under 1 ns per lookup against the 2.9 ns lock round trip they remove (plan review, 2026-10-07); the queued lock is MCS (Mellor-Crummey and Scott, TOCS 1991) in Linux's qspinlock form (4.2, 2015).
- **No wake-affine; ping-pong gets an explicit direct switch** (no wake-affine: user, 2026-10-07, at 25c; the call's form: coordinator, 2026-10-07): steps 28 and 28a. Placement heuristics that guess a waker and wakee share a core are the bug class Lozi et al. found in Linux ("The Linux Scheduler: a Decade of Wasted Cores", EuroSys 2016), and Linux's `wake_affine` has been reworked repeatedly over regressions; so 28 keeps deterministic placement and the landed deferred-kick rule, and a caller that wants its partner on its core says so with `call`. Precedent: L4's direct process switch (Liedtke, "Improving IPC by Kernel Design", SOSP 1993) and seL4's IPC fastpath (Heiser and Elphinstone, "L4 Microkernels: The Lessons from 20 Years of Research and Deployment", TOCS 2016); Linux's `FUTEX_SWAP` (Oskolkov, 2020: proposed, never merged); Android Binder's synchronous transactions, whose server thread takes the caller's priority. Pipes first, as one call over two pipe handles: no new object, and `reply_wait` is the same call; a channel object waits for a user.
- **Strict priority stays global across cores** (coordinator, 2026-10-07): step 28. Per-core queues do not weaken "the highest effective priority runs": per-level bitmaps of running and waiting cores steer each wake to the core running the lowest level below it and let a core about to run lower request the higher task, so step 29's "RT always beats fair" holds machine-wide, up to one hand-off.

## Notes

- Kernel code still never preempts itself: a trap runs to completion under its locks (the big lock until 26a and 28 split it), so the bounded-work rules (`MAX_BUFFER`, `MAX_MAP`, the path and `readdir` limits until step 31; from step 31 `CHUNK`, the 16-component walk chunk and its named exceptions) now also bound how long other cores wait. A `sync` holds the lock for its flushes (about 137 us); phase 7's async block path removes that, or step 32 splits the file system out.
- `Lock<T>` and `PerCpu<T>` live in `arch` because `UnsafeCell` access needs `unsafe`; the kernel crate stays lock-free data behind the board, so its host tests need no lock.
- AArch64 broadcasts inner-shareable TLB and icache maintenance in hardware, so the SGI exists only for waking and rescheduling cores (idle wake, kill, wake preemption), never for shootdown.
- What phase 6 needs from this model: the probe-then-access helpers (`at s1e0r/w`) return `EFAULT` on a page not yet present (demand paging) or copy-on-write (the futex CAS), so kernel user access becomes fault-in-and-retry (step 27 already adds the exception fixup that turns a fault inside a copy into `EFAULT`); and a page-in must never run under `KERNEL`, or every core stalls for the disk.
- A chunked call's frame holds advanced x2-x4 between chunks, so the exception channel and libc-built signals (later phases) deliver only at a call's final return, or restore x2-x4 from the task slot before delivering.
- MogFS v1's limits (`MAX_BLOCKS`, `MAX_INODES`, `MAX_FILE_SIZE`) and the virtio queue depth are phase 7's.
- Shared-memory futexes (keyed by frame), `wait_many`, an affinity API, scheduling domains, nested groups, signals and the exception channel are later phases.
