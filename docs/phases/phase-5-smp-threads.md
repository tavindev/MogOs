# Phase 5: SMP, Threads and Fair Scheduling

Goal: several cores run threads of one process under a fair scheduler with resource groups. The locking model is fixed first, so every later shared table (page cache, network stack) is built on it.

## Steps

Each done-when names its e2e test (a QEMU boot test in `crates/e2e/tests/boot.rs`; host unit tests only for tricky pure logic), the benchmarks it must hold and the ones it adds, and the invariants it keeps. Benchmarks are hvf medians of 21 interleaved boots against the step's base commit (`docs/BENCHMARKS.md`); "hold" means within noise, and a slowdown is a failure: removed, or shown unavoidable with numbers. The tracked kernel benchmarks are yield (`test=bench`, 70 ns), syscall (`test=bench-syscall`, 29 ns), pipe (`test=bench-pipe`, 374 ns) and boot (178 us without a disk); from step 25a they are measured at `-smp 1` and `-smp 4`. The e2e harness runs under TCG on a loaded host, so done-whens assert scheduler state and order, or a median of N samples under a loose ceiling, never a single wall-clock bound.

Step 25a (bring-up: `arch` boot, the secondary entry, per-core GIC and timer) runs in parallel with steps 26-27 (process/thread split and wait-on-address, one core). 25b (the scheduler per core) needs all three and rebases onto 26's process table; 28-31 follow in order.

| 25a | SMP bring-up | `kmain` starts the secondaries with PSCI `CPU_ON` (HVC, like `SYSTEM_OFF`; core count from the DTB, at most `MAX_CPUS` = 4) without waiting for them, so boot pays only the calls. The secondary entry is asm in `arch`: x0 (`CPU_ON`'s context id) carries its 16 KiB stack top (allocated before `CPU_ON`); before any load, store or atomic it loads MAIR, TCR and TTBR0 (the boot table), does a local `tlbi vmalle1` and sets SCTLR; `enable_mmu` is split so the table fill runs once, on core 0. All other scenarios stay at `-smp 1`. Benchmarks: yield, syscall, pipe, boot hold at `-smp 1` and `-smp 4`. Keeps: step 24's lock rules; boot pays no wait for secondaries. |
| 25b | Scheduler per core | Idle contexts are per core, not scheduler slots (no slot or ASID spent): `Scheduler` keeps `current` per core, `advance(cpu)` returns the highest-priority ready task not running elsewhere, or none, and the board then resumes that core's idle frame, which loads the boot table (`set_ttbr0(boot_table, 0)`), so no core keeps walking a dead process's tables. The boot context stays slot 0, pinned to core 0, and leaves `Blocked(Idle)` only when no task is ready and no other core runs one. One run queue under the big lock for now. The reschedule SGI wakes idle cores: making a task ready while a core idles signals that core, and an exit that drops `tasks()` signals core 0. Remote kill: `kill` marks the task and signals its core; any switch away from a marked task ends it instead of saving it, and the IRQ handler ends `current` if marked. The runners and the e2e harness boot `-smp 4` from here, and AGENTS.md's target line changes with them; ordering and benchmark scenarios stay `-smp 1` (`test=yield`, `test=preempt`, `test=pi`, `test=bench`, `test=bench-syscall`, `test=bench-pipe`, `test=bench-disk`, `test=bench-fs`), the rest move to `-smp 4`. e2e `test=smp` grows: with the timer off, four kernel tasks each increment a shared atomic and spin until it reads 4 (on fewer cores this never ends), then print their core: four distinct ones; a process with one thread spinning on another core and one blocked on a pipe is killed, both end, and every frame comes back (`assert_no_leak`). Benchmarks: yield, syscall, pipe, boot hold at `-smp 1` and `-smp 4`; `test=bench-lock` adds contended acquire + release (four cores on one lock; informational, since vCPU preemption dominates it), and asserts that a counter incremented under the lock is exact. Keeps: slot 0 never exits; every frame is charged to a budget; step 24's lock rules. |
| 26 | Threads | Process state moves out of the per-slot arrays into a process table in `kernel` (`Processes<P>`: address space, `Handles`, `Memory` with the budget and map cursor, live thread count, generation); a task slot keeps its frame, state, priorities and kernel stack, and names its process. The ASID is the process index; index 0 is the kernel (boot table, ASID 0); the `<= 256` const assert moves to `MAX_PROCESSES`. New syscall `thread(entry, stack, tls, arg)` starts a thread in the caller's process at the caller's priority, its kernel stack charged to the process budget (the user stack is the caller's own mapped memory), and returns a thread handle (wait, kill, duplicate, transfer); `wait` on it is join and returns its exit code. New `thread_exit(code)` ends the calling thread, and the process ends with its last thread; `exit` (0) still ends the whole process (musl's `exit` and `exit_group`), and `Process` handles keep their meaning. Ending a process with threads on other cores marks and signals them; the last thread to leave a core does `flush_asid` and `free_space`, and the process index (its ASID) is freed only after that. A new thread's frame gets SP_EL0 = `stack` and TPIDR_EL0 = `tls`; `switch_el0_regs` now runs on every switch between user tasks (its "only when switching address spaces" premise no longer holds), and only the TTBR0 write is skipped when the next task shares the space. A sibling thread can rewrite user memory mid-syscall, so inputs the kernel parses (paths, spawn args, handle lists) are copied into a kernel buffer once, then validated; bulk data moves by raw copy, never through a `&[u8]` into live user memory; the `user_bytes` SAFETY rule is rewritten to match. e2e `test=threads` (one core): a process starts four threads that each add 1 to a shared counter 100000 times with an `ldxr`/`stxr` loop and `thread_exit` with their TPIDR_EL0; the main thread joins each (four distinct TLS values) and prints 400000; a process with one thread blocked on a pipe and one spinning is killed, both end, and `assert_no_leak` holds. Host tests: slot and process generations, last-thread exit, a zombie process. Benchmarks: yield, syscall, pipe, boot hold; new thread create + join round trip (ns), and yield between two threads of one process (no TTBR0 write; at most the cross-process yield). Keeps: handle values, generations and rights rules; a failed `spawn` or `thread` changes nothing; zombie and `reap` rules, now per process; one-level PI. |
| 27 | Wait-on-address with PI | New syscalls: `futex_wait(addr, expected, deadline)` blocks while the aligned `u32` at `addr` equals `expected` (read under the big lock, so a wake after a store is never lost; `deadline` in counter ticks, 0 for none, else `ETIMEDOUT`); `futex_wake(addr, n)` wakes up to `n` waiters, highest priority first, and returns the count; `futex_lock(addr)` / `futex_unlock(addr)` are the PI pair: the word holds the owner's thread id (0 when free; slot plus generation in the bits below the waiters bit, so an id never names a later thread), the uncontended path is a CAS in user space, and contended the kernel sets the waiters bit with an `arch` CAS on the user word (probed like `user_bytes_mut`), boosts the owner through `effective`, and `futex_unlock` hands the lock to the highest-priority waiter and `unboost`s; `EDEADLK` for the owner. The owner id must name a live thread of the caller's process, otherwise the caller takes the lock with `EOWNERDEAD`; each thread keeps a list of the PI words it owns with waiters, and its exit wakes them (so they get `EOWNERDEAD`). The key is (process, address): private only, since shared mappings arrive in phase 6. The wait table holds one entry per blocked task, so it is `MAX_TASKS` long and never full. A deadline is the kernel's only sleep: each core caches its earliest deadline and rearms its timer only when that moves earlier (a late fire just rechecks), so neither the switch path nor `yield` scans the table or writes the timer. `thread_exit` gains musl's clear-tid-and-wake (a tid address given to `thread`, zeroed and woken at exit) and a new `unmap` call frees pages (musl's detached threads unmap their own stack). Hard cutover: the kernel mutex object goes (syscalls 9-11, `Mutexes`, `Object::Mutex`, `Event::Lock`, `MAX_MUTEXES`; users `pi.rs`, `high.rs`, `low.rs` and the `crates/user` stubs), its numbers taken by the new calls; this removes cross-process locking until phase 6's shared mappings. Prerequisite: step 23 (musl). e2e: `test=pi` rewritten over `futex_lock` with threads of one process, same priorities and assertion (the owner outruns the middle-priority spinner); `test=futex`: four threads take a lock built on `futex_wait`/`futex_wake` around a plain counter, 100000 times each, and the total is exact; a 5 ms `futex_wait` returns `ETIMEDOUT` no earlier than its deadline (median of 11 under a loose ceiling); a forged owner id gets `EOWNERDEAD`; a C test over musl (`clone` with thread flags maps to `thread`, `futex` to these calls, `exit` to `thread_exit`, `exit_group` to `exit`) runs pthread mutex, condvar and join and prints its result. Host tests: the wait table (keys, wake order, deadlines). Benchmarks: yield, syscall, pipe, boot hold; new uncontended lock + unlock in user space (below the syscall round trip, which proves it makes no syscall), `futex_wake` with no waiter, and a wait/wake ping-pong between two threads (ns). Keeps: PI is one level (`unboost` doc); after an unlock that wakes a higher-priority task the caller switches at once if `outranked()`; user memory is reached only through the probing helpers; no ambient authority (a PI boost reaches only the caller's own threads). |
| 28 | Per-CPU run queues, wake preemption | Each core gets its own run queue: one index list per priority level, linked through the task table (no heap), so `advance` costs the number of levels, not a scan of every slot; blocked tasks hang on per-event lists, so `wake(event)` touches only its waiters; free slots are a free list. Placement is deterministic, with no heuristics: a woken task goes to the core it last ran on; if that core runs an equal or higher priority and another core idles, to the lowest-numbered idle core. A woken task that outranks its core's current task preempts it at once, locally by switching or remotely by the reschedule SGI (phase 3's "a wake does not preempt yet" ends here; 25b already wakes idle cores). An idle core pulls one task from the longest queue before `wfi`. Still one big lock; the queues get their own locks only if step 31 shows it. e2e `test=smp-sched` (`-smp 4`): four kernel spinners each keep one core for a second (each records every core it ran on: exactly one); a top-priority thread blocked on a pipe, with all four cores busy with low-priority spinners, is picked before its core's next tick (asserted from the scheduler's switch record, not wall time); `test=pi` passes with owner and waiter on different cores. Benchmarks: yield, syscall, pipe, boot hold at `-smp 1` and `-smp 4`; new `test=bench-wake`, cross-core wake latency from a pipe write on one core to the reader's return on another (ns, hvf median). Keeps: the highest effective priority runs, round robin within a level (now per core); one-level PI; the boot context stays on core 0; the switch path does not allocate. |
| 29 | Fair class (EEVDF) | Levels 1-3 stay the strict-priority RT class with PI; level 0 becomes the fair class, scheduled per core by EEVDF: each task has a weight (1024 by default) and a virtual runtime; a task is eligible when its lag is not negative, and the eligible task with the earliest virtual deadline (vruntime + slice * 1024 / weight) runs. Vruntimes are kept relative to the queue's minimum vruntime, so the weighted average cannot overflow. Runtime is charged from `CNTVCT_EL0` at each switch and tick; a sleeper keeps its lag, clamped to one slice; a pulled task keeps its lag against the new core's virtual time; `yield` moves the task's deadline one slice on, so two yielding tasks still alternate (`test=yield`). One base slice constant (about 3 ms), no tunables; the slice end joins step 27's cached earliest event, and the timer is rearmed only when that moves earlier (a yield's new slice end is always later, so yield pays nothing). The pick is a linear scan of the core's fair tasks (bounded by `MAX_TASKS`; an indexed heap only if a benchmark asks). RT always beats fair, and PI lifts a fair owner to its waiter's RT level. Boot-spawned programs keep the top RT level (the tests rely on it) except the shell init (`msh`, busybox), which starts fair, so typed commands share the CPU fairly. e2e `test=fair` (`-smp 1`, or the hogs just take separate cores): two kernel hogs at weights 2048 and 1024 split one second 2:1 within 5% (from the scheduler's runtime accounting); beside four hogs, a task waking every 2 ms (`futex_wait` deadline) is picked at its wake while its lag stays within one slice plus the largest single charge; an RT task is picked at its wake ahead of the fair hogs (both asserted on scheduler state). Host tests: eligibility, deadline order, lag kept and clamped across sleep, lag kept across a pull, ties broken by slot, no overflow at 256 tasks of maximum weight. Benchmarks: yield, syscall, pipe, boot hold: `test=bench`'s kernel tasks (level 0) now run fair, so yield gates the fair pick, and syscall and pipe (top RT level) gate the RT path. Keeps: RT before fair; one-level PI; determinism (same inputs, same order). |
| 30 | Resource groups | A group is a kernel object reached by a handle (fixed table `Groups<G>`, entries by index and generation like pipes): a CPU weight (the group is one entity in each core's fair queue and its tasks share its time; groups do not nest), a CPU bandwidth (quota per period, a token bucket refilled each period; an overrun carries into the next period, so tokens can go negative and the long-run share holds; a group out of tokens has its fair tasks off the queues until the refill), and a task cap (live threads, counted at `spawn` and `thread`; over the cap is `EAGAIN`). Memory stays the per-process budgets, which already nest through `spawn`. New syscalls: `group(weight, quota_us, period_us, max_tasks)` creates one whose limits are no looser than the caller's group, `group_set` narrows or loosens within the same bound (write right); `spawn` takes an optional group handle (default: the caller's group), threads stay in their process's group, and boot processes start in the root group (no limits). RT tasks are capped by priority, not bandwidth. e2e `test=groups` (`-smp 1`): a hog in a group capped at 25% beside an uncapped hog gets 25% within 3% over a second (from the scheduler's accounting); groups weighted 2:1 holding one and three hogs split the CPU 2:1, not 1:3; a `thread` past the cap fails with `EAGAIN` and succeeds after a join; closing the last handle to a group frees it once its tasks have ended. Host tests: the token bucket with carried overrun, and the group entity in the fair pick. Benchmarks: yield, syscall, pipe, boot hold (group accounting rides the fair switch path); none new. Keeps: no ambient authority (a group only through its handle, limits only within the creator's); budgets unchanged; RT before fair. |
| 31 | Tables sized for SMP, lock split by measurement | Fixed tables grow, still fixed and fallible (the next object fails with its error, never a panic): tasks 8 to 256, processes 64 (ASIDs stay 8-bit), pipes 16 to 128, handles 16 to 64 per process, groups 16, the wait table equal to tasks; the sizes and the kernel memory they cost are written in the board's CLAUDE.md. The tables stay zero-initialized, outside `.data` (`KERNEL` is in `.data` because `Fs::new` builds a non-zero file system, so the tables move out of it or the file system does), so the image and boot do not grow. Step 28's lists removed the run-queue and wake scans; `Scheduler::end`'s `holds` scan over every handle table (64 x 64 entries per exit) is replaced by a per-process count of outstanding `Process` handles. The one hot-path scan left is step 29's fair pick over a core's fair tasks, named with its measured cost at 256 tasks; other linear scans are on cold paths (create, mount) and named. Each `Lock` counts contended acquisitions per core. `test=bench-smp` runs one, two and four pipe pairs at `-smp 4`, reports aggregate round trips per second and the contention counts; if four pairs reach less than 3x one pair and the counters blame the big lock, the hottest state moves to its own lock (expected order: the run queues, then pipes, then the file system, whose `sync` holds the big lock across its flushes), with the lock order written in the board's CLAUDE.md; otherwise the numbers are recorded and one lock stays. e2e `test=limits`: threads, processes, pipes, handles and groups are created up to each cap, the next fails with its named error, and freeing one lets it succeed; all earlier scenarios pass. Benchmarks: yield, syscall, pipe, boot hold at the new sizes, `-smp 1` and `-smp 4`; new `test=bench-smp` scaling and contention counts. ## Notes

- Kernel code still never preempts itself: a trap runs to completion under the big lock, so the bounded-work rules (`MAX_BUFFER`, `MAX_MAP`, the path and `readdir` limits) now also bound how long other cores wait. A `sync` holds the lock for its flushes (about 137 us); phase 7's async block path removes that, or step 31 splits the file system out.
- `Lock<T>` and `PerCpu<T>` live in `arch` because `UnsafeCell` access needs `unsafe`; the kernel crate stays lock-free data behind the board, so its host tests need no lock.
- AArch64 broadcasts inner-shareable TLB and icache maintenance in hardware, so the SGI exists only for waking and rescheduling cores (idle wake, kill, wake preemption), never for shootdown.
- What phase 6 needs from this model: the probe-then-access helpers (`at s1e0r/w`) return `EFAULT` on a page not yet present (demand paging) or copy-on-write (the futex CAS), so kernel user access becomes fault-in-and-retry (or an exception fixup); and a page-in must never run under `KERNEL`, or every core stalls for the disk.
- Shared-memory futexes (keyed by frame), `wait_many`, an affinity API, scheduling domains, nested groups, signals and the exception channel are later phases.

## What was done

Filled in as each step lands.

- Step 24, lock model (one core): `arch::Lock<T>` (`src/aarch64/lock.rs`) is a ticket spinlock: `next.fetch_add` (an `ldxrh`/`stxrh` pair), then a spin on `ldarh` of `owner` (no `wfe`), release `stlrh` of `owner + 1`. `lock()` masks IRQs, then acquires, and its `Guard` releases, then restores DAIF; `lock_masked()` skips DAIF; `Guard::leak` keeps the lock held until the `unsafe` `Lock::unlock`. `arch::cpu()` reads TPIDR_EL1, which `boot.s` zeroes; `PerCpu<T>` is one `RefCell<T>` per core (`MAX_CPUS` = 4) reached through `with`, IRQs masked, reentry panics (nothing uses it yet). The board's `KERNEL` is `Lock<Kernel>`, `HEAP` and the new `CONSOLE: Lock<Uart>` are leaves (order `KERNEL`, then `HEAP` or `CONSOLE`); the `Global`/`KernelHeap` `UnsafeCell`s, their `unsafe impl Sync`s and every `KERNEL.0.get()` deref are gone, and the kernel crate gained no lock. Every trap hook takes `KERNEL` with `lock_masked` and returns holding it (`Guard::leak`); the trap exit calls the board's `board_unlock` right after `mov sp, x0`, once per trap. `board_irq` now switches through `switch` (it called `task_switch`, which would take the lock twice) and `task_exit` takes the `&mut Kernel` its hook holds. The `brk #0` self-test runs no hook, so `arch::breakpoint_self_test` is `unsafe` and the board takes `KERNEL` before it. Taking a lock is an exclusive RMW, which needs the MMU on, so `kernel::run` now calls `enable_mmu` before the hello line and the self-test (the lines print in the same order), and the board installs the DTB's PL011 into `CONSOLE` there. `Board::console` is a `Console` whose `write_fmt` holds `CONSOLE` for a whole line; panic, fault, echo and user `write` output stay on `UART0` unlocked, so a panic under the console lock still prints. No syscall fast path skips the lock: `dispatch` reads the caller's handle table on every call, including `bench-syscall`'s 0-byte write. e2e `lock_bench_reports_round_trips_and_an_exact_count` (`test=bench-lock`, two new `Board` methods `lock_round_trips` and `add_locked`): both locks' uncontended round trips, then two kernel tasks under the timer each add 10^7 to a counter under the lock; the first to finish has seen the other's additions (the timer interleaved them) and the total is exactly 2 * 10^7; every existing scenario passes unchanged. Benchmarks (hvf, base `9462ef0`, 63 interleaved runs, order alternating, load 6 to 13; median/min before -> after): pre-declared delta, one uncontended ticket round trip per trap, `bench-lock`'s 2.9 ns (min 2.8); yield 70/65 -> 70/67 ns, syscall 30/28 -> 32/29 ns, pipe 375/365 -> 389/378 ns (six traps per round trip, so about six lock round trips), boot 197/181 -> 208/182 us, rerun 195/179 -> 200/175 us (an A/A run of one kernel spread 6 us, so boot holds). Test-and-set (`swap(true, Acquire)`, `store(false, Release)`) costs 6.1 ns (min 6.0) under hvf against the ticket lock's 2.9, so no faster safe form replaces the ticket lock (TCG, informational: 4.3 against 7.1).
