# Phase 4: Shell and Storage

Goal (milestone): from a shell on the console, `ls`, `mkdir`, create a file, write to it, and save; after a reboot on the same disk image, the directory and file contents are still there. POSIX userland (musl, busybox) follows the milestone.

## Steps

Steps 18, 20 and 21 are independent and run in parallel; 22 integrates them.

| # | Step | Done when |
| --- | --- | --- |
| 18 | Console input | GIC SPI enabled for the UART; UART receive with a minimal line discipline (echo, backspace, line delivered on Enter). A blocking `io_submit_wait` read on the console handle returns one line. The e2e harness writes to QEMU's stdin and asserts the echoed line and what the program read. |
| 20 | virtio-blk | virtio-blk over virtio-mmio (found in the DTB; legacy vs modern pinned after checking QEMU's default) reads, writes and flushes 4 KiB blocks. Kernel-internal block API (no user handle yet). e2e: boot with a disk image, write a block, flush, reboot, read it back. Throughput benchmark recorded. |
| 21 | MogFS crate | A safe, `no_std` crate over a `Disk` trait (read/write/flush 4 KiB blocks), shared by the kernel and a host `mkfs`. Copy-on-write: every change writes new blocks; `commit` flushes, writes the next superblock (two alternating slots, generation + checksum), flushes. Checksums on every block; a bad block reads as an error. Operations: lookup, readdir, mkdir, create, read, write (whole-file or append is enough), commit. Host-tested with an in-memory disk: round trip, corruption detected, power cut at every write of a commit leaves the old or the new state, never a mix. |
| 22 | Files + native shell (milestone) | Kernel file objects with MogFS and the boot archive behind one interface: `open(dir, name, flags)` (create), `mkdir(dir, name)`, `readdir`, read/write through `io_submit_wait`, `sync` (commit). `..` and absolute paths cannot escape a directory handle. A tiny native shell (`msh`, `crates/user`) with `ls`, `mkdir`, `touch`, `write <file> <text>`, `cat`, `sync`. e2e: boot 1 runs `mkdir docs`, `write docs/a.txt hello`, `sync`; boot 2 on the same image runs `ls docs` and `cat docs/a.txt` and sees `a.txt` and `hello`. |
| 23 | musl + busybox | musl's `syscall_arch.h` replaced by a dispatcher from Linux syscall numbers to native calls (anything else returns `-ENOSYS`); the fd table is a libc map over handles; stdin/stdout/stderr are fixed handle slots at spawn. `posix_spawn`/`vfork` map to native spawn; `fork` returns `ENOSYS` for now. Signals: `^C` kills the foreground child through its process handle; `SIGCHLD` comes through `wait`; others are ignored. busybox (no-fork configuration, to verify) runs `sh`, `ls`, `cat`. Needs a C cross toolchain on macOS. |

## Notes

- The filesystem lives in the kernel (monolithic), behind the file-object interface. MogFS logic is a pure crate so it is host-tested without QEMU.
- `msh` exists to reach the milestone without a libc port; busybox replaces it as the default shell in step 23.
- A shared-memory submission ring is a later optimization of step 15's completion path, only if its benchmark justifies it.
- Linux binary compatibility comes after this phase (see ROADMAP).

## What was done

Filled in as each step lands.

- Step 18: `kmain` turns on the GICv2 (`arch::gic::enable`: distributor, CPU interface, priority mask), unmasks the PL011's SPI (`gic::unmask`; `UART_IRQ` = 33, hardcoded like the timer's PPI 27; its reset level-sensitive config and, on a one-core GIC, read-as-zero target need no writes) and turns on the UART's receiver and receive interrupt (CR, IMSC.RXIM) on `UART0`, the address that also drains it; `start_timer` now only unmasks its PPI. IRQs stay masked in boot context as before, so input is handled only while a task runs or the boot context idles. `board_irq` drains the UART (reading the last byte clears the level interrupt) into `kernel::console::Line`, a 256-byte buffer in the kernel's IRQs-masked state holding completed lines typed ahead and the line being edited: printable ASCII is appended and echoed (dropped once the buffer is full, keeping room for `\n`), 0x7f and 0x08 erase one char of the line being edited with a `\b \b` echo, `\r` or `\n` ends it with `\n` (a `\r\n` pair yields an empty line, left to the shell), anything else is ignored. Each completed line wakes `Event::Console`. `io_submit_wait(console, IO_READ, ptr, len)` (read right) returns the first completed line, capped at `len` (the rest of that line is dropped), or blocks on `Event::Console` with the `svc` rewound; the buffer is checked before the line is taken, so `EFAULT` never consumes it; zero-length reads return 0 at once. One reader at a time: with two, whichever runs first after the wake gets the line and the other blocks again. init's console handle is now read, write, duplicate, transfer. `test=echo`: `echo` prints `E: ready`, reads two lines, then prints `got: <line>` for each; the e2e harness (stdin piped for this test only, written once `E: ready` appears; stdout now read by a thread) sends `hel`, 0x7f, `lo\r`, `bye\r` in one write and asserts the echo `hel\b \blo` and `bye`, then `got: helo` and `got: bye`, and equal free frames. `crates/kernel/tests/console.rs` covers echo, both backspaces (not past a completed line), ignored control bytes, a full buffer, lines typed ahead, and short and empty reads. The receive FIFO (with its timeout interrupt) was measured and not adopted: pasting a 248-byte line took 1 (hvf) and 3 (TCG) receive interrupts without it and 2 and 1 with it (medians of 5), 2770 vs 2828 us under TCG, since QEMU refills the one-byte holding register as soon as the handler reads it. `crates/user/Cargo.toml` gains an empty `[workspace]`, so its nested build also works from a worktree inside the main checkout. hvf medians, 21 interleaved vs `63591f4` (before/after): yield 66/68 ns, syscall 28/28 ns, pipe 367/364 ns; boot 194/214 us (min 178/177), and over 30 more interleaved boots about 189/200 us: +11 us (6%) for the six MMIO writes (each a hypervisor exit) that set up console input.
- Step 20: virtio-blk over modern (version 2) virtio-mmio. QEMU 9.2 defaults the transport to legacy, so the runners and e2e pass `-global virtio-mmio.force-legacy=false`; modern takes three 64-bit queue addresses where legacy needs a page-size register and one page-aligned ring block, and a legacy transport reads as no disk. `Dtb::virtio_mmio` walks every `virtio,mmio` node (`reg_of` now takes a callback, called once per matching node), and the board's `VirtioBlk::new` probes each for magic, version 2 and device ID 2, requires `VIRTIO_BLK_F_FLUSH` (QEMU keeps its write cache only when it is negotiated) and negotiates it with `VIRTIO_F_VERSION_1`, then sets up one 4-entry split queue in one frame from the frame allocator (descriptors, available and used rings, request header and status), after `init_frames`. Every request is the same chain at descriptor 0 (header, data, status; a flush skips the data), so the zeroed available ring never changes, only its index; the device is told not to interrupt (`VIRTQ_AVAIL_F_NO_INTERRUPT`) and the driver polls the used index: one request in flight, synchronous calls, one MMIO exit (the notify) per request (interrupt completion waits for the GIC SPI work). The kernel's block API is `kernel::Disk`: `read(block, &mut [[u8; BLOCK]])`, `write(block, &[[u8; BLOCK]])` (`BLOCK` = 4096; any number of consecutive blocks in one request) and `flush`, each `Result<(), i64>`; `Board::disk(&dtb)` returns the board's implementation. The device moves data straight to and from the caller's blocks (no bounce copy): the driver accepts only buffers inside the identity-mapped RAM GiB, where every kernel buffer's virtual address is its physical one, and returns `EFAULT` otherwise (a user-space address never reaches DMA); a failed request or an overflowing block number is `EIO` (-5, new); an empty read or write does nothing (QEMU fails one). `run` prints `disk: found` or `disk: none` after the `boot:` line, so probing the 32 transports does not count toward boot time. No user handle yet. `test=disk`: reads blocks 1-2 in one request; if they hold the test pattern, prints `disk: read ok`, otherwise writes them in one request, flushes and prints `disk: wrote` (empty reads and writes are checked too). e2e boots twice on one zeroed temp image (`wrote`, then `read ok`) and checks bytes 4096..12288 of the image on the host, so a block-to-sector mix-up fails; the plain boot test asserts `disk: none`. Same lines under hvf. `test=bench-disk` writes 2048 sequential blocks (8 MiB) and flushes, then reads them back, at 4 KiB and then 256 KiB per request. Speed work: zero-copy DMA (the bounce copy was about 0.5% of a 4 KiB request), one exit per request, multi-block requests (hvf 256 KiB: 3415 MiB/s write+flush, 8629 read, against 148 and 188 at 4 KiB; QEMU's per-request host work, about 20 us, bounds the 4 KiB case, so batching is the lever), and `-global virtio-mmio.ioeventfd=off` (QEMU handles the notify in the vCPU thread: 4 KiB +9% write, +19% read, 21 interleaved hvf boots). Not done: several scattered requests in flight (needs a submit/complete API, best with interrupts) and `VIRTIO_RING_F_EVENT_IDX` (only helps with several in flight). hvf medians, 63 interleaved boots vs `63591f4`: yield 70/70 ns, syscall 29/29 ns, pipe 378/379 ns, boot 203/205 us (noise). `crates/user/Cargo.toml` gets an empty `[workspace]` so the board's nested user build works from a worktree under the main checkout. Step 21/22: MogFS defines its own `Disk` trait; integration picks one (MogFS cannot depend on `kernel`, so likely MogFS's, implemented for `VirtioBlk`).
- Step 20 review: `test=disk` gets a third boot on a fresh image behind `blkdebug` that fails every host flush with EIO (`-blockdev` raw over blkdebug, `inject-error` on `flush_to_disk`); the kernel prints `disk: flush failed`, so the e2e proves the flush reaches the host (with the flush call removed it prints `disk: wrote` and fails, checked). The driver reads the capacity (config 0x100, sectors / 8), exposed as `Disk::blocks`, and rejects a request past the last block with `EIO` (one checked add and compare, which also replaces the sector overflow check); `run` prints `disk: <n> blocks`, and `test=disk` checks that a read straddling the last block is `EIO`. A transport whose setup fails gets status `FAILED` (128). `Board::disk` hands the device out once (`DISK_TAKEN`). Probe cost: the device ID is read first, so an empty transport costs one read (the DTB vouches for the magic value, which is no longer read; ACKNOWLEDGE and DRIVER go in one status write); QEMU `virt` fills transports from the highest address down, so the board scans the DTB's list (ascending, `crates/dtb/tests/virt.rs` with a `dtc`-compacted QEMU blob) in reverse and stops at the first block device, correct for any order. The probe now runs before the `boot:` line (its print after), so boot time includes it. hvf boot medians, 21 interleaved boots on a busy machine: `63591f4` 186 us without a disk, 193 with one; `7d25464` (main, step 18) 205 / 214; this branch 254 / 271 (min 206 / 239 against 185 / 181). Without a disk the cost is the 32 device-ID reads, each a VM exit: the floor for a probe that is correct on any transport order (stopping at the first empty transport would cost one read on QEMU but miss devices elsewhere). With a disk it is one read plus the setup's 23 register accesses (reset, features, status checks, capacity, queue addresses, ready), each required by the virtio 1.2 init sequence or the capacity check. Polling stays as it is: a timeout would need a device reset to recover the queue.
- Step 20 probe: QEMU `virt` fills virtio-mmio transports from the highest address down with no gaps (we never pass an explicit `virtio-mmio-bus.N`), a board fact like `UART_IRQ`, so the board scans from the top and stops at the first empty transport (device ID 0; `VirtioBlk::new` returns the ID it found when it is not a usable block device): no disk costs one MMIO read, and a disk is found on the first. Timed per access under hvf, the setup's register accesses cost about 1 us each except the reset write (about 20 us: QEMU resets the device) and the first capacity read (about 18 us: QEMU refreshes the whole config); the reset write is skipped when status already reads 0, which the spec defines as reset (status is one more 1 us read). In-kernel timing of `Board::disk`: 8 us without a disk (the read plus the full DTB walk that lists the transports), about 45 us with one. Release/acquire on the ring indices in place of two of the three fences (review L1) measured the same (hvf medians, 21 interleaved: 178/221/3488/8510 against 178/223/3473/8281 MiB/s), so the fences stay. hvf boot medians, 21 interleaved against `7d25464`: no disk 234 against 205 us, disk 257 against 204 (mins 203 against 179, 234 against 186); the run-to-run spread on the busy machine (about 20 us) exceeds the 8 us the probe adds without a disk.
- Step 20 transports: QEMU `virt`'s virtio-mmio transports are fixed (32 from `0x0a00_0000`, `0x200` apart), a board fact like `UART0` and `UART_IRQ`, so the board hardcodes them (`VIRTIO`, `VIRTIO_STRIDE`, `VIRTIO_COUNT`) and no longer walks the DTB for them; `Board::disk` takes no `Dtb`, and the dtb crate is back to main's (no `virtio_mmio`, no fixture). `Board::disk` timed in the kernel, 21 hvf boots each: no disk median 2 us (min 1; was 8 with the DTB walk), disk median 50 us (min 45).
- Step 21: `crates/mogfs` ([CLAUDE.md](../../crates/mogfs/CLAUDE.md)), safe and `no_std`, no dependencies; the on-disk format is described at the top of `src/lib.rs`. Two superblock slots (generation `g` in slot `g % 2`) point at an 8-block inode table (504 inodes of 64 bytes: kind, size, 14 direct block pointers, so files hold up to 57232 bytes); inode numbers stay fixed while blocks move, so step 22's handles can hold them. Directories are files of 56-byte entries (names up to 51 bytes). Every block ends in a 64-bit hash of its block number and payload (16 multiply-rotate lanes over words; any one-word change is detected), and a mismatch is `Error::Corrupt`. API: `Fs::new` (const) and in-place `format`/`mount` (`Fs` is about 48 KiB; nothing builds it on a stack, and its largest frame on the kernel target is 640 bytes), `lookup`, `readdir`, `kind`, `mkdir`, `create`, `read`, `write` (overwrite or extend; gaps read as zeros), `truncate`, `commit`. Its `Disk` trait (slices of 4 KiB blocks, `Error`, `blocks`) is the only one: the kernel re-exports it with `BLOCK_SIZE`, and the board's `VirtioBlk` implements it, every failure (EIO, EFAULT before) being `Error::Io`; `test=disk` and `test=bench-disk` print as before. For the fewest I/Os the inode table lives in memory: mount reads both superblocks and both slots' tables; a change writes its data blocks (in place if allocated since the last commit) and marks its table block dirty, allocating that block's new number then, so `NoSpace` is decided up front and changes nothing; `commit` writes the dirty table blocks, flushes, writes the other slot, flushes, and does nothing if nothing changed. Free space is incremental: a `replaced` bitmap of newest-slot blocks the working tree dropped, so at commit the new reachable set is `(newest & !replaced) | (used & !committed)`; blocks reachable from either slot stay reserved, so a fallback mount always finds an intact tree, and blocks dropped before their first commit (`truncate`) are free at once. A free counter and an allocation hint replace popcounts and full scans. One data block stays buffered. Block I/O per operation, `[reads, writes, flushes]` (asserted by `block_io_per_operation`): mount `[4, 0, 0]`, lookup in a one-block directory `[1, 0, 0]` (a two-block one `[2, 0, 0]`, then `[1, 0, 0]` for an entry in the buffered-out first block), create `[1, 1, 0]`, 100-byte write `[0, 1, 0]` (an append to the buffered block too), commit `[0, 2, 2]` (one table block and the superblock), commit with no change `[0, 0, 0]`, read `[1, 0, 0]`. Host benchmark medians (`cargo bench-host`, interleaved with the first version): create+write+commit 6054 -> 2207 ns, lookup in 400 entries 1579 -> 825 ns. `examples/mkfs.rs` writes an empty image through a file-backed `Disk`. Not yet: unlink, rename, a block cache (step 22 measures it on virtio), multi-block requests at commit (dirty table blocks rarely end up adjacent).
- Step 21 review: mount sets the block count from the newest slot before loading the older one, uses the older slot only with the same block count and valid pointers, returns `Io` on any read error (only `Corrupt` falls back), falls back to the older slot when the newest's table is corrupt, and rejects a slot whose generation is in the wrong slot or a block reached twice within one slot; `format` zeroes both slots and flushes before anything else; directory entries need a block (pointer 0 is `Corrupt`), and names `readdir` hands out are validated like `add`'s (`lookup` validates its query instead, so a stored bad name never matches); a write to a block clears the buffer that caches it. Every on-disk value is range-checked once when decoded, so a crafted image gives `Corrupt` or a fallback, never a panic. After `Io` from a change, writes and commits fail until the next `mount`; `Io` from `commit` means unknown. Tests (`tests/fs.rs`, 16): the test disk has a write-back cache, and a power cut at every write and flush of a transaction lands none, all, only the superblock, or all but one of the pending writes, always leaving exactly the old or the new state (removing commit's first flush fails it); a superblock that landed before a failed final flush; round trip and remount in place; `kind`, `truncate`; corruption and fallback; crafted superblocks, records and entries with valid checksums; an older slot past the newest's block count; `Io` at mount; space reuse; limits; `NoSpace` changing nothing; block I/O counts.
- Step 21 review 2: a record is `Corrupt` if it is free with a size or has a pointer past its size (a crafted free record could alias a live block, which reusing its inode released); after a fallback mount the damaged newest slot's table blocks stay reserved, so no write can reseal it as valid; a failed `mount` leaves the file system read-only until a `mount` succeeds; generation `u64::MAX` mounts and the commit after it is refused with `Corrupt` before any I/O. `src/tests.rs` runs 200 seeds of 400 random changes, commits and remounts on 20 to 120-block disks that panic on a write to a block either slot reaches, and after every commit compares the bitmaps and free count with a fresh mount's (it catches `*committed = reach` in `commit` and a missing `hint = min(..)` in `release`). Commit's bitmap pass and the free count cover only the disk's words, and `add` resumes its free-inode scan where it last stopped: create + write + commit 2221 to 2004 ns (host medians, 3 interleaved runs of 51), lookup unchanged (822 against 824).
- Step 22 (milestone): files and `msh`. Objects `Dir(Inode)` and `Node(Inode)` (a MogFS file) join `Archive` and `File`; `Object` stays `Copy` and 24 bytes, with no offset in it: `io_submit_wait` takes the file offset in x4 (files need it, a read at or past the end returns 0; the console and pipes ignore it, so the asm programs' leftover x4 is harmless), and libc will keep fd offsets (step 23). `open(dir, path, len, flags)` now takes flags (`CREATE` makes a missing file, `TRUNC` calls `truncate`; both need write) instead of rights: the result gets the directory handle's rights, so a child never has more, and the archive callers pass 0. New syscalls `mkdir` (13), `readdir` (14: whole `name\n` entries, `name/\n` for a directory, from index `start`; the caller advances `start` by the newlines; `EINVAL` if the next entry does not fit) and `sync` (15: `commit`, write right; `EIO` means unknown). mogfs errors map to musl errnos (`ENOENT`, `EEXIST`, `ENOTDIR`, `EISDIR`, `EINVAL`, `EFBIG`, `ENOSPC`, `EIO` for `Io` and `Corrupt`); the archive answers `open` and `readdir`, and `mkdir` or `CREATE`/`TRUNC` on it is `EROFS`. Paths are walked in the kernel (`kernel::file`): one `lookup` per `/`-separated component, which rejects `.`, `..` and empty names, so `../x` and `/x` are `EINVAL` and a path never leaves its directory handle. The disk work a file syscall does with IRQs masked is bounded: at most 16 path components (`ENAMETOOLONG`, found by a security scan of the first version), each lookup or `readdir` scan at most a directory's 14 blocks, at most 64 entries per `readdir`, file I/O capped by `MAX_BUFFER`; `crates/kernel/tests/file.rs` covers the walk's limits and `readdir` at every buffer size around its entries (the first version could write past a tight buffer when two directories needed their `/`), and `tests/exec.rs` the archive listing. Trust note: a crafted image can point an entry at `ROOT` or an ancestor, so a subdirectory handle may reach the root and the tree may cycle; the walk is bounded by the path's length and nothing recurses over the tree. The board's `KERNEL` static holds `Fs<FsDisk>`, built by the const `Fs::new` (in `.data` with the rest of `KERNEL`: the image grows by 48 KiB); `FsDisk` forwards to `FS_DISK`, where `Board::mount` stores the `VirtioBlk`, since mogfs has no way to replace an `Fs`'s disk. `run` mounts after the probe and before the `boot:` line when a disk exists, except under `test=disk` and `test=bench-disk`, which keep the raw device; a failed mount prints `fs: <error>` (a zeroed image: `fs: Corrupt`), never formats, and processes then get no root handle; mounted, every boot-spawned process gets the root (read, write, duplicate, transfer) as handle 3. Disk I/O runs in the syscall with IRQs masked: a `sync` holds the core for its writes and two flushes. mogfs's `readdir` callback cannot call `kind`, so `kernel::file::readdir` writes up to 64 names with room for a `/` each, then asks `kind` and shifts the directories' entries right. `msh` (`crates/user/src/bin/msh.rs`, the `test=shell` init, handles 0 console and 3 root): prompt `msh> `, one console line per command, empty lines ignored; `ls [dir]`, `mkdir`, `touch` (open `CREATE`), `write <file> <text>` (open `CREATE | TRUNC`, the text and a newline at offset 0), `cat` (reads with advancing offsets), `sync`, `exit` (the boot then powers off); a failure prints `msh: <command>: <errno name or number>`, an unknown command `ENOENT`. e2e `shell_files_survive_a_reboot_only_once_synced` formats a temp image through mogfs (a file-backed `Disk`, mogfs a dev-dependency of e2e), boots `mkdir docs`, `write docs/a.txt hello`, `sync`, `write docs/b.txt late`, `ls docs` (`a.txt`, `b.txt`), `exit`, then reboots on the image for `ls` (`docs/`), `ls docs` (only `a.txt`: the unsynced `b.txt` is gone), `cat docs/a.txt` (`hello`), `cat ../x` and `cat /x` (`msh: cat: EINVAL`); the harness now types one command per prompt so no echo interleaves with output. Human path: `[ -f disk.img ] || cargo mkfs; cargo shell` (string aliases; the drive options follow the runner's `-kernel <path>`). `test=bench-fs` (`fsbench`) times through syscalls, hvf medians of 21 boots: `open(CREATE | TRUNC)` + 100-byte write + `sync` + `close` 137 us (one data write, then commit's table write, flush, superblock write, flush), `open` + `close` 111 ns. hvf medians, 21 interleaved boots against `30aa3cd` (before/after): yield 70/70 ns, syscall 29/29 ns, pipe 376/375 ns, boot without a disk 202/197 us; boot with a MogFS disk 245/386 us, the mount (4 block reads and the in-memory tables), which the pinned design puts inside the boot timing.
