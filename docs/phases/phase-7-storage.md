# Phase 7: Storage that scales

Goal (milestone): MogFS holds a file of at least 1 GiB with snapshots. On the host, a power cut at every write and flush of a workload that writes, snapshots and deletes snapshots always mounts to exactly the old or the new committed generation, with every snapshot intact. In QEMU, a 1 GiB file written through the file API survives `sync`, a snapshot, an overwrite and a QEMU kill at sampled points; scrub then reports a data block the host flipped in the image, naming its file and offset. (A cut at every write is a host test: QEMU can only be killed at sampled points.)

## Steps

Steps 39-41 are pure: `crates/mogfs` only (safe, `no_std`, no `alloc`, no dependencies), host-tested on the Mac, needing no SMP and no virtual memory change, so they run in parallel with phases 5 and 6. Step 39 fixes the format (root table included); 40 and 41 then run in parallel. Steps 42-45 integrate with the kernel and wait on phases 5 and 6 (each lists what it needs); 43 and 44 run in parallel after 42, 45 follows 44.

### Step details

- **39.** Benchmark (host, `cargo bench-host`): create + 100-byte write + commit and lookup in 400 entries must not regress from 1956 / 784 ns; new rows: lookup in 100k entries, 1 GiB sequential write + commit and read on the in-memory disk (MiB/s), mount (requests and ns); requests per operation stay asserted exactly by `block_io_per_operation` (v1: commit `[0, 2, 2]`, a small commit on v2 must match). hvf: `test=bench-fs` round trip (136717 ns) and open + close (111 ns), boot with a mounted disk (342 us); the board's `Fs` static grows with its fixed memory, so the mount cost is measured, not assumed. Invariants: v1's (no block reachable from either slot is written; every on-disk value range-checked once; `NoSpace` decided before anything changes; sticky `Io`), plus: inode numbers are 64-bit and never reused, so a handle can never reach a later file; a data block is a whole 4096-byte page. Avoids: btrfs's fragmentation and ENOSPC reputation by keeping one tree and one CoW path; ext4's rename-without-fsync data loss (M8) because the committed state is always a consistent snapshot (a written contract in `src/lib.rs`).
- **40.** Benchmark (host): snapshot create (requests, ns), a 4 KiB overwrite + commit in a snapshotted 1 GiB file, snapshot delete on a 1 GiB disk (requests, ns). Invariants: a block is free only if no root (live, last committed, any snapshot) reaches it; snapshots are read-only; commit never fails for space. Avoids: btrfs's ENOSPC near full, where deleting needed space it did not have (a reserve only delete and commit draw from).
- **41.** Benchmark (host): scrub MiB/s on the in-memory disk (hash-bound). Invariants: scrub only reads; each slice does at most a fixed number of requests; a report names the block, never guesses a repair (one copy, no redundancy yet). Avoids: silent corruption that ext4 and XFS cannot detect without separate tooling (dm-integrity); here every byte is covered by a checksum its parent holds.
- **42.** Needs phase 5 step 24 (lock model: the file-system task and the syscall path share `Fs`) and step 28 (a completion wakes a task on another core). Benchmark (hvf): `test=bench-disk` grows a 4 KiB random-read IOPS row at queue depth 1 and 32, sequential 4 KiB and 256 KiB rows must not regress from 148 / 188 / 3415 / 8629 MiB/s; `test=bench-fs` round trip; the worst IRQ latency during a `sync` (was the whole sync); syscall, yield and pipe within noise. Invariants: rights are checked and buffers pinned at submit; the file-system task holds no authority of its own, only the op it was handed, charged to the submitter's budget (D8); every op has exactly one completion, cancelled or not. Avoids: POSIX AIO and `O_NONBLOCK` that does not apply to files, which forced user-space thread pools (M9), and io_uring's privileged workers (D8).
- **43.** Needs 42. If phase 6 steps 35-36 landed first, their cache fills switch to v2 extents (whole pages, nothing to strip). Benchmark (hvf): 1 GiB sequential write + `sync` and read through the file API (MiB/s), snapshot create latency, scrub MiB/s. Invariants: a snapshot handle is read-only, whatever rights opened it; scrub and snapshot need the `Volume` handle (no ambient authority). Avoids: `CAP_SYS_ADMIN`-style overloaded privilege for snapshots (M6).
- **44.** Needs phase 5 steps 25 and 28 (SMP bring-up, per-CPU run queues). Benchmark (hvf, `-smp 4`): 4 KiB random-read IOPS at queue depth 32 per core, 1 core against 4; one-core numbers do not regress from 42. Invariants: a request is completed on the CPU that submitted it; no lock is shared between CPUs on the submit path. Avoids: the single-lock request queue blk-mq had to replace, and its I/O scheduler zoo (one scheduler, `none`).
- **45.** Needs 44. Benchmark (hvf): sequential 256 KiB MiB/s and 4 KiB random IOPS per core, NVMe against virtio-blk. Invariants: DMA only into kernel-owned buffers in the identity map, as virtio-blk; a failed or timed-out command is `Io`, never a hang. Avoids: driver-specific block APIs; every device implements one `Disk`.

## MogFS v2 format (decided in step 39)

- One copy-on-write B+tree per root, keyed by (inode, kind, offset or name hash): inode items, directory entries (hashed, collisions chained in the item), extents. One CoW, checksum and walk path serves every structure.
- Tree nodes are 4 KiB blocks ending in v1's checksum of block number and payload; every pointer also carries its child's checksum and birth generation (a Merkle tree), so a lost or misdirected write of a valid old block is caught.
- Data blocks are whole 4096-byte pages, no trailer: an extent (at most 128 blocks, 512 KiB) carries its blocks' checksums inline. A data block maps 1:1 to a page for phase 6's cache and file mmap, and DMA reaches it directly. Ripple for phase 6 step 35: on v1 its fills strip the 8-byte trailer; on v2 they do not.
- Two alternating superblock slots, as v1; the superblock holds the root table (a fixed number of entries: the live tree and the snapshots, each a tree root and an allocation-bitmap root) and a small allocation log, so a small commit writes its leaf and the superblock, as v1 does; bitmap blocks are rewritten when the log fills.
- Free space is stored, not derived: every root has a copy-on-write allocation bitmap; a block is free only if the live, the last committed and the pinned bitmap (the union of the snapshots', kept on disk, rebuilt when a snapshot is deleted) all have it clear. Mount reads the superblock and the bitmap blocks (one per 128 MiB of disk), not the whole tree.
- Fixed memory, no `alloc`: the caller gives `Fs` its node cache and bitmap memory, sized for the largest disk it accepts; a larger disk is a named error at mount. Dirty nodes may be written early to their new, unreachable blocks, so the cache bounds memory, not transaction size.
- Space reserve: each change reserves its worst case (tree height, bitmap blocks) before changing anything, as v1's `reserve`; a fixed reserve below that is open only to unlink, truncate, snapshot delete and commit.
- 64-bit sizes, block numbers and inode numbers; names up to 255 bytes; inode numbers come from a counter and are never reused. The kernel's `EBUSY`-on-open `unlink` rule stays until a step chooses otherwise (never-reused numbers make dropping its scan safe).
