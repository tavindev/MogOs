# Phase 6: Virtual Memory

Goal: memory is paid for when it is promised and materialized when it is touched. `map` charges the budget up front (the commit charge, so no overcommit and never an OOM killer) and frames appear on first touch; a kernel-owned page cache, capped only in what no budget pays for, serves `read`, `write` and file mappings; libc builds `fork` over a budget-charged copy-on-write clone; the kernel moves to the higher half (TTBR1) with every byte of RAM mapped, guarded kernel stacks and a randomized base, so user VA has no kernel or GIC hole. Every step is held to the moat: the fastest form that is completely safe, a benchmark slowdown is a failure unless shown unavoidable with numbers, invalid states are unrepresentable through zero-cost types, and `unsafe` stays in `arch` and the board.

## Steps

Each done-when names its e2e test (a QEMU boot test in `crates/e2e/tests/boot.rs`; host unit tests only for tricky pure logic), the benchmarks it must hold and the ones it adds, and the invariants it keeps. Benchmarks are hvf medians of 21 interleaved boots against the step's base commit (`docs/BENCHMARKS.md`), at `-smp 1` and `-smp 4`; "hold" means within noise, and a slowdown is a failure: removed, or shown unavoidable with numbers, its delta pre-declared before the step's code is written. The tracked set: yield (`test=bench`, 70 ns), syscall (`test=bench-syscall`, 29 ns), pipe (`test=bench-pipe`, 374 ns), boot (178 us without a disk), spawn round trip (`test=bench-spawn`), thread create + join (`test=bench-threads`), the per-call rows of `test=bench-syscalls` (`map` of one page: 552 ns), `test=bench-smp`, and the `scripts/oscompare.sh` rows against Linux (`spawn`, `file-read`); numbers are the step's base, which phase 5 will have moved. The e2e harness runs under TCG on a loaded host, so done-whens assert counts and state (frames materialized, disk requests issued, fault counts), never a wall-clock bound.

Phase 6 starts after phase 5 steps 26a, 27, 28 and 31, and names each use: **26a** gives the per-process lock that the fault path and region table live under, the atomic budget that `map` charges with one CAS, and the lock order every step here keeps (a process lock, then `KERNEL` with the file system, then the process table, then the frame allocator, then `CONSOLE`; no path holds two process locks); **27** gives `unmap` and its TLB sequence (clear, `dsb ishst`, `tlbi` per page, `dsb ish`, then free), and the exception fixup on user copies that 33 turns into fault-in-and-retry; **28** takes `KERNEL` off every syscall fast path, so a page-in never runs under it (phase 5 Notes); **31** sizes RAM, the frame bitmap and the system tables from the DTB at boot, and gives the worst-case table count a mapping can need. The page cache lives under the file system's lock (35), so the file system is the one lock level the cache adds nothing to. Order: 33 first (the frame table, regions and the fault path every later step builds on). Then 33a, then 34 (both rework process construction; 34 rebases on 33a). 35 needs 33 and the file system under its own lock; 36 needs 34 (private file pages break CoW through its path) and 35. **The table is not strictly sequential**: 37 (higher-half) touches `arch`'s MMU code and the board's layout, not the fault path, so it may run in parallel with 33a-36 once 33 has landed (33 already reaches frames through `arch::kva`, so 37 changes one function); 37a follows 37, and 38 follows 37a. Phase 7 steps 42-43 switch 35's fills to MogFS v2's `map` (if 42 lands first, a fill is a request to its file-system task and 35's split of the file system out of `KERNEL` is already done); phase 8 step 52 needs 33 and 35.

| 33 | Frame table, regions, demand paging | **Frame table** (`mm`, safe, host-tested): one `AtomicU32` per frame of RAM, sized at boot beside step 31's bitmap (0.1% of RAM), counting a frame's holders (each mapping, and from 35 the page cache); 34 and 35 build on it. The allocator hands out `Frame`, a non-`Copy` owner of one frame's `PhysAddr` that `free` consumes, so a double free no longer compiles (today it is a run-time `assert!`); `unmap_page` returns an `Unflushed<Holder>` that only the `TlbFlushed` token `arch::flush_*` returns turns into a `Holder`, whose drop decrements the count and yields `Option<Frame>`, `Some` only at 0, so every unmapper of a shared or cache frame, last or not, decrements only after its own flush; `free_space` frees only those frames. **Regions**: each process's address space is a sorted array of `Region { start, end, access, kind }` in its `Process` (26a, under its lock), stored in a board frame run charged to the process that doubles like step 31's `grow_handles` (`ENOMEM` changes nothing); `kind` is `Anon` (from 33a `Image`, from 36 `File`) and `access` an enum of `ReadOnly`, `ReadExecute` and `ReadWrite`: no variant is writable and executable, so user W^X is a type, not a check. The map cursor goes. **`map(pages, flags)`** charges `pages` plus the tables the range can need that no region already pays for (a level-3 table per 2 MiB span and a level-2 table per GiB it touches, counting only those its neighbors in the sorted array do not already cover: step 31's formula, made to compose) in one CAS (26a) and inserts a region; no frame, no zeroing, no table, so `MAX_MAP` (64 KiB per call) goes and musl's `do_mmap` loop with it; `ENOMEM` only at `map`, over the budget or with no gap below `USER_END`. Flag `POPULATE` materializes every page at once (today's eager path, for callers that will touch all of it). `unmap` (27) removes or splits regions and refunds each page's charge, touched or not, and the table charge of each 2 MiB span and GiB no remaining region covers; a split changes no table charge. **Fault reserve**: each thread holds one frame, charged with its kernel stack at `thread` and `spawn` and zeroed only when a fault uses it, so the fault path never allocates while a page's frame is in flight and frames never exceed charges. **The fault path** (`board_user_fault`, EL0 data or instruction abort, translation or permission fault at level 1-3): under the process lock, binary-search the region; none, or an access the region forbids, kills the process as today (`fault:` line). If the PTE already allows the access, the fault was a stale entry left by a local-only upgrade (34): `tlbi vale1` by VA and ASID, `dsb nsh`, return. Otherwise unlock, zero the thread's reserve frame, lock, recheck the region, its access and the PTE (an `unmap` or a sibling may have changed any of them: on a change keep the reserve and return to retry), install with `map_page` (invalid to valid, so no TLB maintenance: `dsb ishst` only), unlock, then refill the reserve from the allocator (the page's charge now backs it; if the allocator is empty, 35's reclaim, holding no lock). **User copies**: the `at s1e0r/w` probes in `UserIn`/`UserOut` go (under hvf each cost about 23 ns, phase 5 step 26); the copy routine moves bytes with `ldp`/`stp` behind `mask_user` or with `ldtr`/`sttr` (EL0's permissions applied by the hardware, 8 bytes per instruction, no pair form), chosen in this step by `bench-pipe`, a 56 KiB `read` and `bench-fs` (Decided); 60b's `mask_user` keeps every pointer in user space, and 27's fixup turns a fault inside the copy routine or the futex CAS into a return naming the faulting address; the board then runs the fault path for it (as if EL0 had touched it, with the access the copy needed) and retries, so `EFAULT` means no region or a forbidden access, never "not yet touched". A page-in holds no lock but the process lock (28). Address-space teardown frees in `CHUNK`-sized batches, one frame-allocator lock hold per batch (step 31 named it O(pages) under the lock). Every user frame and table is reached through `arch::kva(PhysAddr)` (identity until 37). e2e `test=demand` (`-smp 4`): a process with a 96 MiB budget maps 64 MiB and touches 1 MiB: `Board::frames_used` grows by 256 frames plus tables, not 16384; a second 64 MiB `map` fails with `ENOMEM` at `map`, since only about 32 MiB of budget is uncommitted though 63 MiB of the first map were never touched; a console `write` from a mapped page never touched writes its zeros, from an unmapped address returns `EFAULT`, and a `read` into a `ReadExecute` page returns `EFAULT`; four threads touching the same fresh page at once leave one frame mapped and each keeps a reserve; an EL0 store to a read-only region prints `fault:`; `unmap` of a half-touched range refunds the whole charge; `assert_no_leak`. Host tests: region insert, split and lookup against a linear model on random sequences; the frame table's counts. Benchmarks: yield, syscall, pipe, boot, spawn, thread create + join hold; syscall pre-declared faster (no probes); pipe and file reads hold or improve with the chosen copy form, both forms' numbers recorded; thread create + join pre-declared to pay one more frame allocation and free (the reserve) and must hold; `map` one page pre-declared faster (no zeroing, no table walk); new `test=bench-fault`: first-touch fault (ns per page) and `map` + touch-every-page of 1 MiB, lazy and `POPULATE`, against the base's eager `map`: lazy pays one EL0 abort per page on top of the same zeroing (pre-declared: about one syscall round trip per page), `POPULATE` must equal the base, so a caller that touches everything loses nothing; `bench-smp` gains a fault mode (k processes, then k threads of one process, each first-touching 4 MiB) that shows whether the process lock or the frame allocator's lock contends. Keeps: no overcommit (every page and its tables charged at `map`; frames in use never exceed charges; a fault never fails for memory); `unsafe` only in `arch` (table writes, `kva`, the copy routine) and the board; user W^X by type; a frame's count drops only after the TLB maintenance that unmapped it (`Unflushed<Holder>`, above). |
| 33a | User image and stack sized from the ELF | The 2 MiB `IMAGE` window, the one-to-two-page native stack and the fixed `MAP_BASE` go. `Elf::parse` checks segments against user space (`USER_BASE..USER_END`) instead of `IMAGE`. Each `PT_LOAD` becomes an `Image` region with its own access: `ReadExecute` for text, `ReadOnly` for read-only data (today it maps executable for lack of the kind: `UserAccess::ReadOnly` is new in `arch`, UXN and AP read-only), `ReadWrite` for data and bss. Spawn charges the whole image, stack and their worst-case tables at once (33's rule) and copies nothing: a first touch copies the page from the boot archive (the rest zeroed) and, for an executable page, cleans it to the point of unification and runs `ic ivau` over that page alone (not `ic ialluis`). The entry page and the top stack page (which holds the arguments) are populated at spawn, so a program that touches one page of each, `nop`, takes no fault. **The stack**: its size is `PT_GNU_STACK`'s `p_memsz` (set by `lld -z stack-size=`), or 128 KiB (`STACK_DEFAULT`, musl's `__mog_start` size today) when 0, at most the budget; it is a `ReadWrite` region ending at `USER_END` with a 1 MiB unmapped gap below it that no `map` may take (Linux's `stack_guard_gap`), and every user program is built with stack probes, so no frame larger than the gap can jump it: Rust's inline stack probes in the user target spec and `-fstack-clash-protection` for musl, busybox and `c/` (clang; aarch64 support checked in this step's plan review). Probes cost instructions only in functions whose frame passes a page. The stack budget is that charge: a program that wants more says so in its ELF. The map cursor's start is the image's end rounded up to 2 MiB. musl's `__mog_start` uses the stack it is given and stops mapping its own 128 KiB, and `crates/user` and `c/` link with `-z stack-size`. e2e `test=image`: a program with a 4 MiB bss and a 1 MiB stack (`-z stack-size=0x100000`) touching one page of each materializes two frames beyond its populated ones; a store to its rodata faults (`fault:`, data abort permission); a branch into its rodata faults (instruction abort); recursion past its stack faults in the gap, and a function with a 2 MiB local array faults in the gap through its probe rather than landing past it; a program whose image does not fit its budget fails `spawn` with `ENOMEM`; every existing scenario (busybox, msh, `oscb`) passes. Benchmarks: spawn (`nop`) holds (no fault: entry and stack pages populated); thread create + join, syscall, yield, pipe, boot hold; `oscompare` `spawn` (`oscnop` through musl, 18.0 us against Linux's 18.5) pre-declared faster by the eager copy of about 10 program pages, 5 of bss and the 32-frame stack zeroing it no longer pays (BENCHMARKS.md item 1). Keeps: W^X per segment by type (a segment that is writable and executable is rejected at parse, as today); everything spawn charges is refunded on failure. |
| 34 | CoW clone and libc `fork` | New syscall `clone(budget)`: a new process whose address space is a copy-on-write copy of the caller's and whose handle table holds each of the caller's handles that carries `DUPLICATE`, at the same handle value (generation and index) and with the same rights, so libc's fd table stays valid; the rest are left out, so a clone gains no authority `dup` would not give. One thread: a copy of the caller's frame with x0 = 0, at the caller's priority. The caller gets a `Process` handle (wait, kill). The child's budget (`budget` frames moved from the caller, or 0 for the group's, phase 5 step 30) is charged up front for the caller's whole commit, every region's pages touched or not and their tables, plus its kernel stack and fault reserve; so a clone fails with `ENOMEM` and changes nothing, and never overcommits. The copy walks the regions under the caller's process lock: `Anon`, `Image` and private `File` pages present in the caller are mapped into the child at the same frame, each frame's count goes up, and writable ones become read-only in both; shared `File` regions (36) are not copied and refault. Then `dsb ishst`, one `tlbi aside1is` for the caller's ASID (the permission drop), `dsb ish`. Only the calling thread is cloned; sibling threads run on during the copy. **CoW fault**: a write fault on a read-only page in a `ReadWrite` region: if the frame's count is 1 (no other mapping, and not a cache page, whose cache holder keeps it at 2 or more), the PTE is made writable in place and only this core's stale entry is dropped (`tlbi vale1` by VA and ASID, `dsb nsh`; another core's stale read-only entry takes one spurious fault, which 33's path answers with the same local TLBI); otherwise copy into the thread's fault reserve (filled before the lock, as 33), then break-before-make: clear the PTE, `dsb ishst`, `tlbi vale1is`, `dsb ish`, write the new PTE, drop the old frame's holder (freed only at 0), and refill the reserve. libc: `fork` is `clone` plus the pid table and `atfork` handlers; an fd whose handle lacks `DUPLICATE` is closed in the child; `vfork`, `posix_spawn` and `exec` stay on `spawn` with an explicit handle list, so no handle leaks across an exec. e2e `test=fork` (C, musl): the child writes a global and a heap page and the parent still reads its own values, and the parent's own write after the fork does not reach the child; the child's `_exit(7)` is the parent's `waitpid` status; a process whose commit exceeds its remaining budget gets `fork` = -1 with `ENOMEM` and keeps running; a process with two threads forks a child with one; an fd whose handle lacks `DUPLICATE` is closed in the child and every other fd works unchanged; after both exit `assert_no_leak` holds and every frame count is 0. Host tests: the frame-count transitions (share, break, reuse, last unmap). Benchmarks: yield, syscall, pipe, boot, spawn, thread create + join hold (the count update rides only unmap and CoW); new fork round trip (`fork` + `_exit` + `waitpid`) with 1 MiB and 32 MiB touched, the parent's first write to a page after a fork (the CoW break, ns per page), and an `oscompare` `fork` row against Linux. Keeps: no overcommit (the child pays for its whole view up front); a frame is freed only when its count reaches 0 and only after the TLB maintenance of its last unmap; no handle crosses without `DUPLICATE`. |
| 35 | Page cache | The file system's pages are cached in kernel-owned frames outside every budget (Decided, ROADMAP), all under the file system's lock: each inode with cached pages has a radix tree (64-way nodes from the heap, at most three levels for a 1 GiB file, one leaf per 64 cached pages, each node freed with its last page, so node memory is bounded by the cache; a node allocation that fails reclaims and retries, so no heap is reserved for nodes) from page index to `CachedPage { frame, flags }`; eviction is S3-FIFO across all files (a small FIFO for new pages, a main FIFO, a ghost FIFO of recently evicted keys, a 2-bit frequency per page), and a hit is one relaxed atomic increment of that counter, never a list move. Cached pages outlive `close`; unlink, truncate and eviction drop them. The cache holds one count on each of its frames (33's table), so a mapped cache page is never reused in place by a CoW fault. `read` and `write` copy between user memory and cached pages; a fault inside that copy releases the file system's lock before 33's fault path runs, and the copy restarts from the page lookup; a miss fills whole pages from MogFS (v1: 4088 data bytes per block after its 8-byte trailer, so a page spans two blocks; phase 7 step 43 switches to v2's `map`), the block's checksum verified first, so a corrupt block returns `EIO` and never enters the cache. `write` stays write-through: it updates the cached pages it covers and MogFS as today, so `read`, `write` and (36) mappings see one copy and `sync`'s meaning does not change. **Memory**: a clean, unmapped page is droppable at once, so the cache may fill any frame no budget has materialized; the invariant is free frames plus droppable pages at least the charged pages not yet materialized (phase 5's sum: budgets never exceed RAM). `reclaim` drops S3-FIFO victims under the file system's lock. The rule that keeps it reachable: no charged frame is taken under a lock below the file system's in 26a's order (the process table, slots, pipes, the frame allocator); a caller that needs frames there takes them before it locks, and an allocation that finds no free frame drops what it holds below the file system's level, reclaims and retries. So 33's fault refill reclaims holding no lock; `map_page`'s table frames, taken under the process lock, reclaim beneath it (26a allows the file system's lock below a process lock); a file fault already holding the file system's lock reclaims under that same guard; spawn, `thread` and pipe creation take their frames before the process-table, slot or pipe lock. What no budget pays for is the fill in flight: fills run one at a time under the file system's lock, so `CACHE_HELD` is one fill's frames, reserved from RAM at boot outside every budget, and nothing waits on it. The fill runs under the file system's lock and never `KERNEL` (phase 5 Notes): if step 32 has not split the file system out of `KERNEL` by then, that split is this step's first commit. e2e `test=cache`: a 56 KiB file (v1's limit) read twice through `io_submit_wait` issues zero virtio-blk requests the second time (`Board::disk_requests`) and returns the same bytes, also after the file was closed and reopened; a write through one handle is read back through another without a disk request; a block the host flipped in the image fails the read with `EIO` and a reread still issues a request; a process that maps and touches its whole budget while the cache holds the free frames succeeds, with `Board::cache_pages` falling; `assert_no_leak` (cache frames counted apart). Host tests: S3-FIFO against a reference model on random and scan traces (a scan of twice the cache leaves a hot set touched twice resident); the radix tree's insert, lookup, truncate and node count. Benchmarks: `bench-syscalls`' `file-read` (64 bytes, 73.6 ns) and `bench-fs` hold or improve; `bench-fault`'s first-touch row holds with the allocator empty and the cache full, so each fault evicts a victim inline; new warm read of a 56 KiB file (ns per KiB) and `oscompare`'s `file-read` within v1's limits, against Linux; yield, syscall, pipe, boot hold. Keeps: the cache is charged to nobody (no first-toucher pays, Linux's memcg complaint, M14); no overcommit; a page enters the cache only verified (`Verified<Page>`, constructed only by the checksum check); 26a's lock order (the cache adds no level). |
| 36 | File mappings | `map` takes an optional file handle and page offset: `READ` for a private or read-only shared mapping, `READ \| WRITE` for a writable shared one. A mapping holds the inode's open count, so `unlink` returns `EBUSY` while it is mapped (today's rule for any handle, `crates/kernel/src/file.rs` `unlink`), and an `open` with `TRUNC` of a mapped file returns `EBUSY` (new: `open` truncates with no check today), so no page of a mapping ever goes past a truncated end. A file region's pages are the cache's frames: under the process lock the fault finds the region, then takes the file system's lock (26a's order); a cached page is mapped at once, and up to 15 more already-cached pages around it, within the region and 64 KiB-aligned, with no I/O (fault-around); a miss unlocks both, fills (35) and retries. A private writable mapping maps them read-only and breaks CoW through 34's path, so a private write never reaches the file. Charges: a file region is charged to the mapper at `map` like `Anon` (a private page may become a copy, and a mapped page cannot be dropped while mapped), refunded at `unmap`; a cache page with a mapping is never evicted, so no reverse map is needed to reclaim. Shared writes: a shared writable mapping maps each page read-only first; its first write faults and, under the process lock then the file system's, marks the page dirty and makes the PTE writable with 34's local upgrade; a page under writeback instead makes the fault drop both locks, wait for the writeback holding none (26a: no process lock spans a switch) and retry from the region lookup. Each inode keeps the list of regions that map it (process index and generation, start, page offset, length) under the file system's lock; `map` and `clone` register a region while holding the process lock, which 26a's order allows. `msync` and `sync` clean a page as Linux's `page_mkclean` does: under the file system's lock mark it under writeback and clear its dirty bit, and copy the mapping list; then, one process lock at a time, write-protect it in every shared mapping whose process generation still matches and whose PTE maps that frame (`dsb ishst`, `tlbi vale1is` per page or `aside1is` past 512, `dsb ish`); then write it through MogFS; then clear the writeback bit and wake waiters. So a store after the clean faults and redirties the page, and none is lost. `unmap` clears its region's PTEs and flushes under its process lock, drops it, then cleans the region's dirty pages as `msync` does before its refund, so it never holds two process locks. A process's exit leaves its dirty shared pages charged to it and its regions holding their inodes' open counts until its reap writes them: that reap runs in the syscall that reaps it (`wait`, or the `close` of its last `Process` handle), holding no lock, never in the trap exit's deferred release; when the last handle goes in the release of an exiting holder, the write passes to that holder's own reap, so the chain ends at a syscall or at init, which never exits (phase 5 has no orphan reaper; named). A fault past the file's end kills the process (SIGBUS's place until the exception channel, phase 9). e2e `test=mmap` (C, musl `mmap`): a private read-only mapping of a 56 KiB file equals `read`'s bytes and its first fault maps all 14 of its pages (`Board::fault_count` is 1); a private write is not in the file; a shared write is seen by `read` at once and on disk after `msync` (a fresh mount), and a store between two `msync`s is on disk after the second; `unlink` and an `open` with `O_TRUNC` of a mapped file are `EBUSY`, and both succeed after `unmap`; a store to a read-only mapping and a load past the end print `fault:`; a forked child (34) of a process with a shared mapping writes through it and the parent sees it; a process that exits with dirty shared pages has them on disk once its parent's `wait` returns; `assert_no_leak`. Benchmarks: yield, syscall, pipe, boot, spawn hold; new mapped read of a cached 56 KiB file (first touch, ns per page) against `read` of it. Keeps: 26a's lock order (process, then the file system; `msync` takes process locks one at a time and never under the file system's lock), checked at compile time; a dirty page is never dropped; a page is never written while a mapping can store to it unseen; no overcommit. |
| 37 | Higher-half kernel, all RAM mapped | The kernel runs from TTBR1 (`TCR_EL1.EPD1` cleared, T1SZ = 25: a 39-bit kernel half like the user half, three-level walks in both), its entries global, and TTBR0 holds only user mappings: process tables no longer copy `KERNEL_ENTRIES` or the GIC GiBs (`gic_gibs` goes), `free_space` skips nothing, and an idle core's TTBR0 is an empty table with ASID 0. Kernel layout: a linear map of every RAM range in the DTB's memory nodes (step 31's 3 GiB cap goes; 256 GiB of linear map is the named cap), 1 GiB blocks where nothing needs finer, with the image's alias and the DTB read-only and everything PXN; the image in its own 2 MiB blocks keeping 60c's text RX, rodata R, data RW and PXN; MMIO (UART, virtio, the GIC distributor and every redistributor region, wherever QEMU puts it) in a device area. `arch::kva` becomes the linear-map offset and `PhysAddr`, `KernelVa` and `UserVa` are distinct newtypes, so a physical address is never dereferenced and a user address never reaches kernel code unmasked. Boot: core 0 builds the TTBR1 tables and a one-block identity map of the image's text (Linux's `idmap_pg_dir`, kept for secondaries), turns the MMU on through it and branches to the high address; the identity map's entries are not global and are loaded only with ASID 0, which no process uses, and a core leaving it for its first TTBR0 runs a local `tlbi vmalle1`, so none of its translations survives into user VA. `USER_END` becomes a constant, 511 GiB (the last GiB stays unmapped), so the redistributor hole past 123 cores is gone. 60b's `mask_user` becomes Linux's single instruction (clear bit 55, so a user pointer can never select TTBR1) and its cost is re-measured into the debt ledger. e2e `test=highmem` (`-m 5G`, TCG): a process with a 4 GiB budget maps 4 GiB with `POPULATE` and then writes and reads back only its last 64 MiB, whose frames lie above physical 4 GiB (`Board::frame_of` checked), so the test pays for no faults; `test=map-end` at `-smp 128` (ignored, TCG): a process maps at user VA 256 GiB (the old hole) and up to `USER_END`; a syscall given a kernel address returns `EFAULT`; an EL0 load of a kernel address prints `fault:`; 60c's `kernel_text_is_read_only...` scenario passes under TTBR1 (text write, data execute, linear-alias write of text each fault). Benchmarks: yield, syscall, pipe, boot, spawn, thread create + join hold; syscall and pipe pre-declared faster by the cheaper `mask_user`; boot pays the larger table fill (linear map in 1 GiB blocks: a few entries per GiB of RAM). Keeps: 60c's invariants (no kernel mapping writable and executable, through any alias); `unsafe` only in `arch` and the board; a user mapping never global and never reaching the kernel half. |
| 37a | Kernel virtual areas: guarded stacks, page-by-page runs | A stack area in the kernel half: each kernel stack (a task's, every core's idle and IRQ path, core 0's boot stack) is 16 KiB of frames mapped page by page into the lower half of a 32 KiB-aligned slot whose upper 16 KiB stays unmapped, the guard of the stack above it. Stacks no longer need contiguous frames, and neither do step 31's multi-page runs, handle tables, region arrays (33) and pipe buffers past one page, which move to a second area mapped page by page: their fragmentation `ENOMEM` (a named cap in phase 5) goes. A single-page object stays in the linear map, so the common pipe and small handle table pay no extra TLB entry. Overflow: a stack overflow can only fault at EL1, so only the vectors for exceptions taken from EL1 check for it (Linux's test: SP with bit 14 set means it left its stack for the guard below; `add`/`sub`/`tbnz`, no register spilled) and switch to a per-core overflow stack that prints `panic: kernel stack overflow` with the task and the faulting address; the EL0 vectors (every syscall, every user IRQ) start at an empty stack's top and run no check. Freed task stacks go to a per-core cache of two still-mapped slots (their frames, two stacks per core, are held out of the root group's budget at boot like `CACHE_HELD`, so a refunded stack never leaves a budget headroom the allocator cannot back; reuse charges the next owner), so a thread create + join maps and flushes nothing in the common case; past the cache a slot's pages are unmapped with `tlbi vaae1is` per page. e2e `test=kstack`: a kernel task recursing past its stack prints the overflow panic naming it (from the overflow stack, so the report itself does not fault); a secondary core's idle stack overflow does the same (`-smp 4`); with the frame allocator fragmented by a fixture so that no two adjacent frames are free, a thread starts, a handle table grows past 8 pages and a 64 KiB pipe is created; `assert_no_leak`. Benchmarks: syscall, pipe, yield hold (EL0 entries unchanged, instruction counts checked under TCG `-icount`); thread create + join and spawn hold (the stack cache); boot holds. Keeps: every kernel stack has a guard; the overflow report never runs on the overflowed stack; `unsafe` only in `arch` and the board. |
| 38 | KASLR | The kernel is linked position-independent (`-C relocation-model=pie`, `lld --pie`, both stable) and `arch`'s boot code applies its `R_AARCH64_RELATIVE` relocations before any absolute address is used. Seed: `/chosen/kaslr-seed` (8 bytes, written by QEMU `virt` every boot unless `dtb-randomness=off`; the net stack keeps `rng-seed`), else FEAT_RNG's `RNDR` where present, else none: the fixed base and `kaslr: off (no seed)`. Randomized: the image's slot (2 MiB-aligned, so its block mappings stay, in a 128 GiB window: 16 bits), the stack area's and the device area's bases (2 MiB-aligned in the remaining kernel VA); the linear map fills its half and stays fixed (named). No KPTI and no fixed-VA vector page (Decided). `TCR_EL1.E0PD1` is set where ID_AA64MMFR2_EL1 reports E0PD (EL0 accesses to the kernel half fault in constant time), and the `spec:` line reports `kaslr: on`, or `kaslr: weak (no E0PD)` on a CPU without it, which includes `-cpu cortex-a72` under hvf and TCG. e2e `test=kaslr`: two boots print different `kaslr: image <va>` bases (printed only under `test=kaslr`, so no other boot log carries the base) and both run every scenario's smoke set; `-M virt,gic-version=3,dtb-randomness=off` boots at the fixed base with `kaslr: off (no seed)`; a panic and a fault report print offsets from the image base so they stay readable. Benchmarks: syscall, yield and pipe hold, with TCG `-icount` instruction counts per round trip equal to the base's: PIE code must reach statics with `adrp` + `add` as today, so any GOT load that lld does not relax to that pair (lld's AArch64 GOT relaxation; checked in the disassembly) is removed before the step lands; boot holds (the relocation pass, measured: a few thousand entries). Keeps: 37's layout invariants at any offset; no kernel address in the ABI (handles, not pointers). |

## Decided

- **Fault path under the process lock, no per-region locks** (coordinator, 2026-10-07): step 33. The reserve frame is zeroed outside the lock, so the lock covers a lookup, a table walk and a store; threads of one process faulting at once serialize only that. Linux needed per-VMA locks because its `mmap_lock` covered the whole fault (merged in 6.4, then weeks of crash fixes for VMA merging races: LWN 937943, "Stabilizing per-VMA locking", 2023). Per-region locks come only if 33's `bench-smp` fault mode shows the process lock contending.
- **A per-thread fault reserve over allocating under the lock or waiting in the allocator** (plan review, 2026-10-07): step 33. Allocating after the lock would hold it across a zeroing; allocating before it lets two racing threads hold two frames for one charged page, briefly more frames than charges, which another process's charged fault could then miss. One pre-charged frame per thread, zeroed at use, costs 4 KiB per thread and one allocation and free per thread's life, and keeps frames at or below charges always, with no wait on the fault path.
- **Regions are a sorted array per process, binary-searched, in a charged frame run** (coordinator; storage from the plan review): step 33. O(log n) lookup, contiguous memory, charged like the handle table (step 31); Linux's maple tree (6.1) serves address spaces with tens of thousands of VMAs and RCU readers, which MogOs does not have.
- **A mapping is charged for the tables it can need, once per 2 MiB span and GiB** (plan review): steps 33, 33a, 34. A lazy fault may need a level-2 and a level-3 table; charging them up front keeps "a fault never fails for memory" without a second budget check on the fault path. A span or GiB already covered by a neighbor is not charged again, and `unmap` refunds those no remaining region covers, so charges compose and match the worst case exactly.
- **TLB maintenance takes the narrowest correct form** (coordinator): steps 33-37, from Linux v6.18 `arch/arm64/include/asm/tlbflush.h` (read 2026-10-07): invalid to valid needs no TLBI ("invalid to valid transition requires no flush"); a changed leaf is `tlbi vale1is` per page between `dsb ishst` and `dsb ish`; a freed table is `vae1is` (walk caches too); past 512 pages one `aside1is` (`MAX_DVM_OPS = PTRS_PER_PTE`). A permission upgrade (CoW reuse, a shared page's first write) drops only this core's entry, and another core's stale read-only entry takes one spurious fault, which the fault path answers with a local `tlbi vale1` and `dsb nsh` (Linux v6.18 `arch/arm64/mm/fault.c`, `__ptep_set_access_flags_anysz`: "Remote stale entries may still cause page faults", `TLBF_NOBROADCAST`). A CoW break changes the output address, so it is break-before-make (Arm DDI 0487, "Using break-before-make when updating translation table entries"; section number unverified here, checked in 34's plan review). That a faulting entry is never held in a TLB, which the first rule rests on, is per the Linux comment; the Arm ARM rule's ID is unverified. Fork pays one `aside1is` on the parent after its writable pages turn read-only, Linux's `dup_mmap` form (unverified this session). AArch64 broadcasts all of these, so no IPI (phase 5 step 25a).
- **User copies: `ldp`/`stp` behind `mask_user` or `ldtr`/`sttr`, chosen by numbers in step 33** (plan review): with the probe gone, the hardware must refuse what EL0 may not do. `ldtr`/`sttr` check EL0's permission per access but move 8 bytes per instruction with no pair form, which slows bulk copies (pipe, a 56 KiB `read`, `bench-fs`, `oscompare` `file-read`). Plain `ldp`/`stp` at EL1 are equally safe while every mapping in user VA grants EL1 exactly EL0's access: `mask_user` keeps the pointer in user VA, no user-VA mapping is EL1-only, and a read-only user page is read-only at EL1 too (AP[2]). PAN: the A72 has none (ARMv8.1) and `SCTLR_EL1.SPAN` is set, so nothing is toggled; on a PAN core the alternative is Linux's `uaccess_enable` around a bulk copy. Unprivileged access becomes required the day a user-VA mapping grants EL1 more than EL0, which no step plans; 33 records the rule beside `mask_user`. Linux arm64 uses `ldtr`/`sttr` (`user_ldst`; unverified this session); the faster of the two by 33's numbers lands.
- **ASIDs stay the process index** (coordinator): steps 33-38. No generation allocator (Linux v6.18 `arch/arm64/mm/context.c`) while live processes fit the ASID width (phase 5 step 31's named cap); TTBR1 entries are global, so the kernel never spends an ASID; the identity map's entries are not global and use ASID 0 (37).
- **Lazy by default, `POPULATE` on request, no zero page, no anonymous fault-around** (coordinator): steps 33, 33a. A caller that touches every page asks for today's eager cost and loses nothing; a sparse caller pays per touched page. A shared zero page would add a second fault to the common write-after-malloc pattern, and anonymous fault-around zeroes pages that may never be touched; each is revisited only with a benchmark (Notes: the 64 KiB experiment).
- **The user stack has a 1 MiB gap and every user program is built with stack probes** (plan review): step 33a. The gap alone is free but a frame larger than it jumps it; probes close that, and cost only in functions whose frame passes a page (Linux's 1 MiB `stack_guard_gap` plus `-fstack-clash-protection`, the Stack Clash response, 2017).
- **Page cache: per-file radix tree, S3-FIFO eviction, under the file system's lock** (coordinator): step 35. A per-file index (Linux's per-`address_space` radix tree, now XArray) makes truncate, unlink and per-file `msync` walk one file's pages in order, where a global hash (the survey's first sketch; Linux 2.4's page hash) scans or rehashes. S3-FIFO as published (Yang et al., "FIFO Queues are All You Need for Cache Eviction", SOSP 2023: FIFO queues, a 2-bit frequency per object, a hit is one counter update with no list move, scan-resistant through the small queue and the ghost queue); a 1-bit frequency is the named variant if the counter shows in profiles. SIEVE (Zhang et al., NSDI 2024) is simpler but keeps no ghost and its authors call it not scan-resistant on some workloads (SIEVE site, "SIEVE is simpler than LRU", read 2026-10-07); MGLRU only if a benchmark asks. Putting the cache under the file system's lock adds no lock level, and eviction runs only where 26a's order allows that lock: no charged frame is taken under a lock below it (35's rule; plan review).
- **The cache caps only what no budget pays for; clean pages use all uncharged RAM** (research, 2026-10-07): step 35. Linux's `dirty_ratio` bounds dirty memory, not the cache (docs.kernel.org, `Documentation/admin-guide/sysctl/vm.rst`), and Fuchsia's per-pager dirty limit does the same (RFC-0226). Dirty pages of shared mappings are paid by their mappers' charges (plan review), so `CACHE_HELD` is the one fill in flight; clean pages are the slack (D2). Mapped file pages are charged to their mappers and pinned while mapped, so reclaim needs no reverse map; a page mapped by two processes is charged to both (named). `bench-fault` must hold with every fault evicting a victim inline.
- **`write` stays write-through; no writeback task in this phase** (coordinator): steps 35-36. One copy for `read`, `write` and mappings without a dirty-page writer; shared writable mappings are the only dirty pages, written at `msync`, `sync`, `unmap` and by the reaper's `wait`. A writeback task with a per-device dirty bound waits for phase 7 step 42's async block path, where it can overlap I/O.
- **A mapping holds the inode open, so `unlink` and truncate are `EBUSY` while mapped** (plan review): step 36. `unlink`'s is today's rule for any handle (`file.rs`'s `unlink`); truncate's is new (`open` with `TRUNC` checks nothing today), so mappings need no orphan inodes and no unmap-on-truncate walk; orphan inodes wait for phase 9's POSIX unlink semantics.
- **Shared pages are cleaned in `page_mkclean` order** (plan review): step 36. Mark under writeback and clear dirty, write-protect every mapping and flush, then write, then clear writeback; a write fault marks the page dirty before it upgrades the PTE, and one that finds the page under writeback drops its locks, waits holding none and retries, so no store is written stale or left unmarked (Linux `folio_clear_dirty_for_io` then `folio_mkclean`, `mm/page-writeback.c`; unverified this session).
- **File fault-around maps up to 64 KiB of already-cached pages** (coordinator): step 36. Linux's `fault_around_bytes` default is 64 KiB (`mm/memory.c`; unverified this session); no I/O is started by it.
- **Fork copies page tables eagerly; shared file regions refault, private ones are copied** (coordinator; private file regions from the plan review): step 34. A private file page may already be a private copy, so it must be copied like `Anon`; a shared one is the cache's frame and refaults. On-demand-fork (Zhao, Gong and Fonseca, EuroSys 2021: page tables shared CoW, 65x faster than fork for 1 GiB processes) waits until 34's 32 MiB fork row shows the table copy dominating. The child pays its whole view up front, so a fork fails cleanly instead of overcommitting (Baumann et al., "A fork() in the road", HotOS 2019; ROADMAP Decided).
- **`clone` passes only handles with `DUPLICATE`, at their own values** (research, 2026-10-07): step 34. Handle values (generation and index) are kept, so libc's fd table maps unchanged and an fd whose handle lacks `DUPLICATE` is closed in the child; `exec` is `spawn` with an explicit list, so the inherit-by-default leak class Python's PEP 446 fixed for `exec` does not arise.
- **39-bit VA in both halves** (coordinator): step 37. Three-level walks keep every TLB miss one level shorter than 48-bit's four; 512 GiB of user VA and a 256 GiB linear map are named caps, above anything QEMU `virt` under hvf gives this host.
- **Kernel stack overflow is checked only on exceptions taken from EL1; freed stacks are cached; one-page objects stay in the linear map** (coordinator; last clause from the plan review): step 37a. Linux runs its `VMAP_STACK` test in every `kernel_ventry` (Linux v6.18 `arch/arm64/kernel/entry.S`: "Task and IRQ stacks are aligned so that SP & (1 << THREAD_SHIFT) should always be zero"); an entry from EL0 starts at the top of an empty stack and cannot overflow there, so the syscall path pays nothing. The two-stack per-core cache is Linux's `NR_CACHED_STACKS` (`kernel/fork.c`; unverified this session).
- **KASLR without KPTI; E0PD where present, reported weak elsewhere; no fixed-VA vector page** (research, 2026-10-07): step 38. Linux enables KPTI with KASLR on a CPU without E0PD (Linux v6.18 `pi/map_kernel.c`, `kaslr_requires_kpti`), since TLB timing of EL0 probes defeats KASLR there, and its Kconfig says E0PD gives KASLR the benefit KPTI does at lower overhead. KPTI roughly doubled syscall overhead and cost hackbench about 10% (Deacon, arm64 KAISER cover letter, LKML 2017-11, lkml.iu.edu 1711.2/01400), and A72 is on Linux's KPTI-safe list, so there it would buy only KASLR: the moat declines it. A fixed-VA vector page (against v3a reading VBAR_EL1) buys nothing either: Linux v6.18 `proton-pack.c` lists every A72 revision as v3a-affected (`MIDR_ALL_VERSIONS(MIDR_CORTEX_A72)`), and on a KPTI-less A72 TLB timing and TPIDR_EL1 (the per-CPU offset from the image's template) reveal the base anyway, while E0PD cores are not v3a-affected; it would cost every exception. So step 38 holds syscall, yield and pipe at equal instruction counts. Seed: `kaslr-seed` from the DT, else `RNDR`, as Linux v6.18 `arch/arm64/kernel/pi/kaslr_early.c`; QEMU 9.2.1 `hw/arm/virt.c` `create_randomness` writes an 8-byte `kaslr-seed` and a 32-byte `rng-seed` into `/chosen` under `dtb-randomness`. A 2 MiB-aligned image offset keeps the block mappings (`pi/map_kernel.c`: `kaslr_seed & ~(MIN_KIMG_ALIGN - 1)`). The `oscompare` notes say Linux on an A72 without E0PD pays KPTI for its KASLR.
- **The mapping seal moves to phase 9 with `mprotect`** (research, 2026-10-07): today it would block only `unmap`. There the kernel seals a spawned program's image regions itself (OpenBSD's `mimmutable`, LWN 915640; Linux's `mseal` documentation). This corrects phase 10's Decided ("the mapping seal stays with KASLR there"), which is left to phase 10's own editor.
- **No huge pages in phase 6** (research, 2026-10-07): 2 MiB transparent huge pages make a forked child's 4 KiB write copy 2 MiB (Redis's latency documentation tells users to disable THP for this); survey step 37 and its numbers are dropped. The fault path and `alloc_contiguous(16)` stay shaped for a later measured 64 KiB experiment (Notes).
