# Phase 6: Virtual Memory

Goal: memory is paid for when it is promised and materialized when it is touched. `map` charges the budget up front (the commit charge, so no overcommit and never an OOM killer) and frames appear on first touch; a kernel-owned page cache under a global cap serves `read`, `write` and file mappings; libc builds `fork` over a budget-charged copy-on-write clone; the kernel moves to the higher half (TTBR1) with every byte of RAM mapped, guarded kernel stacks and a randomized base, so user VA has no kernel or GIC hole. Every step is held to the moat: the fastest form that is completely safe, a benchmark slowdown is a failure unless shown unavoidable with numbers, invalid states are unrepresentable through zero-cost types, and `unsafe` stays in `arch` and the board.

## Steps

Each done-when names its e2e test (a QEMU boot test in `crates/e2e/tests/boot.rs`; host unit tests only for tricky pure logic), the benchmarks it must hold and the ones it adds, and the invariants it keeps. Benchmarks are hvf medians of 21 interleaved boots against the step's base commit (`docs/BENCHMARKS.md`), at `-smp 1` and `-smp 4`; "hold" means within noise, and a slowdown is a failure: removed, or shown unavoidable with numbers, its delta pre-declared before the step's code is written. The tracked set: yield (`test=bench`, 70 ns), syscall (`test=bench-syscall`, 29 ns), pipe (`test=bench-pipe`, 374 ns), boot (178 us without a disk), spawn round trip (`test=bench-spawn`), thread create + join (`test=bench-threads`), the per-call rows of `test=bench-syscalls` (`map` of one page: 552 ns), `test=bench-smp`, and the `scripts/oscompare.sh` rows against Linux (`spawn`, `file-read`); numbers are the step's base, which phase 5 will have moved. The e2e harness runs under TCG on a loaded host, so done-whens assert counts and state (frames materialized, disk requests issued, fault counts), never a wall-clock bound.

Phase 6 starts after phase 5 steps 26a, 27, 28 and 31, and names each use: **26a** gives the per-process lock that the fault path and region table live under, and the atomic budget that `map` charges with one CAS; **27** gives `unmap` and its TLB sequence (clear, `dsb ishst`, `tlbi` per page, `dsb ish`, then free), and the exception fixup on user copies that 33 turns into fault-in-and-retry; **28** takes `KERNEL` off every syscall fast path, so a page-in never runs under it (phase 5 Notes); **31** sizes RAM, the frame bitmap and the system tables from the DTB at boot. Order: 33 first (the frame table, regions and the fault path every later step builds on). Then 33a, then 34 (both rework process construction; 34 rebases on 33a). 35 needs 33 and the file system under its own lock; 36 needs 34 (private mappings break CoW through its path) and 35. 37 (higher-half) touches `arch`'s MMU code and the board's layout, not the fault path, so it may run in parallel with 33a-36 once 33 has landed (33 already reaches frames through `arch::kva`, so 37 changes one function); 37a follows 37, and 38 follows 37a. Phase 7 steps 42-43 switch 35's fills to MogFS v2's `map`; phase 8 step 52 needs 33 and 35.

| 33 | Frame table, regions, demand paging | **Frame table** (`mm`, safe, host-tested): one `AtomicU32` per frame of RAM, sized at boot beside step 31's bitmap (0.1% of RAM), holding a frame's map count; 34's CoW and 35's cache build on it. The allocator hands out `Frame`, a non-`Copy` owner of one frame's `PhysAddr` that `free` consumes, so a double free no longer compiles (today it is a run-time `assert!`). **Regions**: each process's address space is a sorted `Vec<Region>` in its `Process` (26a, under its lock; the `Vec` grows in frames charged to the process, step 31's rule), each `{ start, end, access, kind }` with `kind` `Anon` (and from 33a `Image`, from 36 `File`) and `access` an enum of `ReadOnly`, `ReadExecute` and `ReadWrite`: no variant is writable and executable, so user W^X is a type, not a check. The map cursor goes. **`map(pages, flags)`** charges `pages` to the budget (one CAS, 26a) and inserts a region; no frame, no zeroing, no table, so `MAX_MAP` (64 KiB per call) goes and musl's `do_mmap` loop with it; `ENOMEM` only at `map`, over the budget or with no gap below `USER_END`. Flag `POPULATE` materializes every page at once (today's eager path, for callers that will touch all of it). `unmap` (27) removes or splits regions and refunds each page's charge whether or not it was ever touched. **The fault path** (`board_user_fault`, EL0 data or instruction abort, translation or permission fault at level 1-3): binary-search the region; none, or an access the region forbids, kills the process as today (`fault:` line); otherwise take a frame and zero it **before** the process lock (the frame is charged already, so this cannot fail: phase 5's no-overcommit sum guarantees a free frame or, from 35, a clean cache page to take), then lock, recheck the PTE (a sibling may have installed it: free ours, return), install with `map_page` (an invalid-to-valid change, so no TLB maintenance: `dsb ishst` only), unlock, return to EL0. **User copies**: the `at s1e0r/w` probes in `UserIn`/`UserOut` go (under hvf each cost about 23 ns, phase 5 step 26). 60b's `mask_user` keeps every pointer in user space and 27's fixup turns a fault inside the copy routine or the futex CAS into a return naming the faulting address; the board then runs the fault path for it (as if EL0 had touched it, with the access the copy needed) and retries the copy, so `EFAULT` means no region or a forbidden access, never "not yet touched". A page-in holds no lock but the process lock (28). Address-space teardown frees in `CHUNK`-sized batches, one frame-allocator lock hold per batch (step 31 named it O(pages) under the lock). Every user frame and table is reached through `arch::kva(PhysAddr)` (identity until 37). e2e `test=demand` (`-smp 4`): a process with a 96 MiB budget maps 64 MiB and touches 1 MiB: `Board::frames_used` grows by 256 frames plus tables, not 16384; a second 64 MiB `map` fails with `ENOMEM` at `map` with 32 MiB of budget still unmaterialized; a `write` to the console from a mapped page never touched writes its zeros, from an unmapped address returns `EFAULT`, and into a `ReadExecute` page (a `read`) returns `EFAULT`; four threads touching the same fresh page at once leave one frame mapped (the others' frames freed); an EL0 store to a read-only region prints `fault:`; `unmap` of a half-touched range refunds the whole charge; `assert_no_leak`. Host tests: region insert, split and lookup against a linear model on random sequences; the frame table's counts. Benchmarks: yield, syscall, pipe, boot, spawn, thread create + join hold; syscall and pipe pre-declared faster (no probes); `map` one page pre-declared faster (no zeroing, no table walk); new `test=bench-fault`: first-touch fault (ns per page) and `map` + touch-every-page of 1 MiB, lazy and `POPULATE`, against the base's eager `map`: lazy pays one EL0 abort per page on top of the same zeroing (pre-declared: about one syscall round trip per page), `POPULATE` must equal the base, so a caller that touches everything loses nothing; `bench-smp` gains a fault mode (k processes, then k threads of one process, each first-touching 4 MiB) that shows whether the process lock or the frame allocator's lock contends. Keeps: no overcommit (every page charged at `map`, a fault never fails for memory); `unsafe` only in `arch` (table writes, `kva`) and the board; user W^X by type; a frame is freed only after the TLB maintenance that unmapped it (`unmap_page` returns an `Unflushed<Frame>` that only the `TlbFlushed` token `arch::flush_*` returns turns back into a `Frame`). |
| 33a | User image and stack sized from the ELF | The 2 MiB `IMAGE` window, the one-to-two-page native stack and the fixed `MAP_BASE` go. `Elf::parse` checks segments against user space (`USER_BASE..USER_END`) instead of `IMAGE`. Each `PT_LOAD` becomes an `Image` region with its own access: `ReadExecute` for text, `ReadOnly` for read-only data (today it maps executable for lack of the kind: `UserAccess::ReadOnly` is new in `arch`, UXN and AP read-only), `ReadWrite` for data and bss. Spawn charges the whole image and stack at once (the commit) and copies nothing: a first touch copies the page from the boot archive (the rest zeroed) and, for an executable page, cleans it to the point of unification and runs `ic ivau` over that page alone (not `ic ialluis`). The entry page and the top stack page (which holds the arguments) are populated at spawn, so a program that touches one page of each, `nop`, takes no fault. **The stack**: its size is `PT_GNU_STACK`'s `p_memsz` (set by `lld -z stack-size=`), or 128 KiB (`STACK_DEFAULT`, musl's `__mog_start` size today) when 0, at most the budget; it is a `ReadWrite` region ending at `USER_END` with a 64 KiB unmapped gap below it that no `map` may take, so an overflow faults (the stack budget is that charge: a program that wants more says so in its ELF). The map cursor's start is the image's end rounded up to 2 MiB. musl's `__mog_start` uses the stack it is given and stops mapping its own 128 KiB, and `crates/user` and `c/` link with `-z stack-size`. e2e `test=image`: a program with a 4 MiB bss and a 1 MiB stack (`-z stack-size=0x100000`) touching one page of each materializes two frames beyond its populated ones; a store to its rodata faults (`fault:`, data abort permission); a branch into its rodata faults (instruction abort); recursion past its stack faults in the gap; a program whose image does not fit its budget fails `spawn` with `ENOMEM`; every existing scenario (busybox, msh, `oscb`) passes. Benchmarks: spawn (`nop`) holds (no fault: entry and stack pages populated); thread create + join, syscall, yield, pipe, boot hold; `oscompare` `spawn` (`oscnop` through musl, 18.0 us against Linux's 18.5) pre-declared faster by the eager copy of about 10 program pages, 5 of bss and the 32-frame stack zeroing it no longer pays (BENCHMARKS.md item 1). Keeps: W^X per segment by type (a segment that is writable and executable is rejected at parse, as today); everything spawn charges is refunded on failure. |
| 34 | CoW clone and libc `fork` | New syscall `clone(budget)`: a new process whose address space is a copy-on-write copy of the caller's, whose handle table holds each of the caller's handles that carries `DUPLICATE` (same rights; the rest are left out, so a clone gains no authority `dup` would not give), with one thread: a copy of the caller's frame with x0 = 0, at the caller's priority. The caller gets a `Process` handle (wait, kill). The child's budget (`budget` frames moved from the caller, or 0 for the group's, phase 5 step 30) is charged up front for the caller's whole commit, every region's pages touched or not, plus its tables and kernel stack; so a clone fails with `ENOMEM` and changes nothing, and never overcommits. The copy walks the regions: `Anon` and `Image` pages present in the caller are mapped into the child at the same frame, each frame's count goes up, and writable ones become read-only in both; file regions (36) are not copied and refault. Then one `tlbi aside1is` for the caller's ASID (the permission drop), `dsb ish`. Only the calling thread is cloned; sibling threads run on during the copy, which holds the caller's process lock. **CoW fault**: a write fault on a read-only page in a `ReadWrite` region: if the frame's count is 1, the PTE is made writable in place and only this core's stale entry is dropped (`tlbi vale1` with the ASID, no broadcast: another core's stale read-only entry faults once and finds the PTE already writable); otherwise copy into a fresh frame (taken and filled before the lock, as 33), then break-before-make: clear the PTE, `dsb ishst`, `tlbi vale1is`, `dsb ish`, write the new PTE, and drop the old frame's count (freed at 0). libc: `fork` is `clone` plus the fd table, pid table and `atfork` handlers; `vfork` and `posix_spawn` stay on `spawn`. e2e `test=fork` (C, musl): the child writes a global and a heap page and the parent still reads its own values; the child's `_exit(7)` is the parent's `waitpid` status; a process whose commit exceeds its remaining budget gets `fork` = -1 with `ENOMEM` and keeps running; a process with two threads forks a child with one; a handle without `DUPLICATE` is absent in the child; after both exit `assert_no_leak` holds and every frame count is 0. Host tests: the frame-count transitions (share, break, last unmap). Benchmarks: yield, syscall, pipe, boot, spawn, thread create + join hold (the count update rides only unmap and CoW); new fork round trip (`fork` + `_exit` + `waitpid`) with 1 MiB and 32 MiB touched, and an `oscompare` `fork` row against Linux. Keeps: no overcommit (the child pays for its whole view up front); a frame is freed only when its count reaches 0 and only after the TLB maintenance of its last unmap; no handle crosses without `DUPLICATE`. |
| 35 | Page cache | The file system's pages are cached in kernel-owned frames outside every budget (Decided, ROADMAP): each open inode keeps a radix tree (64-way nodes from the heap, at most three levels for a 1 GiB file) from page index to `CachedPage { frame, flags }`, under that file's lock; eviction is S3-FIFO across all files (a small FIFO for new pages, a main FIFO, and a ghost FIFO of recently evicted keys), and a hit stores one frequency bit with a relaxed atomic, never moving the page. `read` copies from cached pages; a miss fills whole pages from MogFS (v1: 4088 data bytes per block after its 8-byte trailer, so a page spans two blocks; phase 7 step 43 switches to v2's `map`), the block's checksum verified first, so a corrupt block returns `EIO` and never enters the cache. `write` stays write-through: it updates the cached pages it covers and MogFS as today, so `read`, `write` and (36) mappings see one copy and `sync`'s meaning does not change; truncate and unlink drop the file's pages. **Memory**: a clean page is droppable at once, so the cache may fill any frame no budget has materialized, and a fault or a kernel allocation that finds no free frame takes the S3-FIFO victim instead: phase 5's sum (budgets never exceed RAM) still guarantees every charged page a frame. What cannot be dropped at once, pages being filled or (36) dirty, is bounded by the global cap `CACHE_HELD` frames, held out of the root group's budget at boot; a fill that would pass it waits. The fill runs under the file system's lock and never `KERNEL` (phase 5 Notes): if step 32 has not split the file system out of `KERNEL` by then, that split is this step's first commit. e2e `test=cache`: a 56 KiB file (v1's limit) read twice through `io_submit_wait` issues zero virtio-blk requests the second time (`Board::disk_requests`) and returns the same bytes; a write through one handle is read back through another without a disk request; a block the host flipped in the image fails the read with `EIO` and a reread still issues a request; a process that maps and touches its whole budget while the cache holds the free frames succeeds, with `Board::cache_pages` falling; `assert_no_leak` (cache frames counted apart). Host tests: S3-FIFO against a reference model on random and scan traces (a scan of twice the cache leaves a hot set touched twice resident); the radix tree's insert, lookup and truncate. Benchmarks: `bench-syscalls`' `file-read` (64 bytes, 73.6 ns) and `bench-fs` hold or improve; new warm read of a 56 KiB file (ns per KiB) and `oscompare`'s `file-read` within v1's limits, against Linux; yield, syscall, pipe, boot hold. Keeps: the cache is charged to nobody (no first-toucher pays, Linux's memcg complaint, M14); no overcommit; a page enters the cache only verified (`Verified<Page>`, constructed only by the checksum check). |
| 36 | File mappings | `map` takes an optional file handle and page offset: `READ` for a private or read-only shared mapping, `READ \| WRITE` for a writable shared one. A file region's pages are the cache's frames: a fault fills the page (35) and maps it, then maps up to 15 more already-cached pages around it, within the region and 64 KiB-aligned, with no I/O (fault-around); a private writable mapping maps them read-only and breaks CoW through 34's path, so a private write never reaches the file. Charges: a file region is charged to the mapper at `map` like `Anon` (a private page may become a copy, and a mapped page cannot be dropped while mapped), refunded at `unmap`; a cache page with a non-zero map count is never evicted, so no reverse map is needed to reclaim. A shared writable mapping maps each page read-only first; its first write faults, marks the cache page dirty (counted against `CACHE_HELD`) and makes the PTE writable with 34's local upgrade. Each inode keeps a list of the regions that map it (process index, start, page offset, length) under its lock, which comes before the process lock (the fault path looks the region up, drops the process lock, takes the file's, then the process lock again and rechecks), so `msync` and `sync` write each dirty page through MogFS and then write-protect it in every shared mapping (`tlbi vale1is` per page, or `aside1is` past 512 pages) before clearing its dirty bit. An exiting process's or an `unmap`'s shared dirty pages are written the same way. A fault past the file's end kills the process (SIGBUS's place until the exception channel, phase 9). e2e `test=mmap` (C, musl `mmap`): a private read-only mapping of a 56 KiB file equals `read`'s bytes and its fault-around maps 16 pages per fault (`Board::fault_count`); a private write is not in the file; a shared write is seen by `read` at once and on disk after `msync` (a fresh mount); a shared mapping survives `unlink` until `unmap`; a store to a read-only mapping and a load past the end print `fault:`; a forked child (34) of a process with a shared mapping writes through it and the parent sees it; `assert_no_leak`. Benchmarks: yield, syscall, pipe, boot, spawn hold; new mapped read of a cached 56 KiB file (first touch, ns per page) against `read` of it. Keeps: the lock order inode, then process, then the frame allocator, checked at compile time (26a's levels); a dirty page is never dropped; no overcommit. |
| 37 | Higher-half kernel, all RAM mapped | The kernel runs from TTBR1 (`TCR_EL1.EPD1` cleared, T1SZ = 25: a 39-bit kernel half like the user half, three-level walks in both), its entries global, and TTBR0 holds only user mappings: process tables no longer copy `KERNEL_ENTRIES` or the GIC GiBs (`gic_gibs` goes), `free_space` skips nothing, and an idle core's TTBR0 is an empty table with ASID 0. Kernel layout: a linear map of every RAM range in the DTB's memory nodes (step 31's 3 GiB cap goes; 256 GiB of linear map is the named cap), 1 GiB blocks where nothing needs finer, with the image's alias and the DTB read-only and everything PXN; the image in its own 2 MiB blocks keeping 60c's text RX, rodata R, data RW and PXN; MMIO (UART, virtio, the GIC distributor and every redistributor region, wherever QEMU puts it) in a device area. `arch::kva` becomes the linear-map offset and `PhysAddr`, `KernelVa` and `UserVa` are distinct newtypes, so a physical address is never dereferenced and a user address never reaches kernel code unmasked. Boot: core 0 builds the TTBR1 tables and a one-block identity map of the image's text, turns the MMU on through it, branches to the high address; secondaries enter through the same identity map, which stays (Linux's `idmap_pg_dir`): one table, EL1-only, in no process's TTBR0. `USER_END` becomes a constant, 511 GiB (the last GiB stays unmapped, `UNMAPPED`'s new home in user VA), so the redistributor hole past 123 cores is gone. 60b's `mask_user` becomes Linux's single instruction (clear bit 55, so a user pointer can never select TTBR1) and its cost is re-measured into the debt ledger. e2e `test=highmem` (`-m 6G`, TCG): a process maps and touches 4 GiB, frames above physical 4 GiB are used (`Board::frames_used` past the old cap), and the bytes read back; `test=map-end` at `-smp 128` (ignored, TCG): a process maps at user VA 256 GiB (the old hole) and up to `USER_END`; a syscall given a kernel address returns `EFAULT`; an EL0 load of a kernel address prints `fault:`; 60c's `kernel_text_is_read_only...` scenario passes under TTBR1 (text write, data execute, linear-alias write of text each fault). Benchmarks: yield, syscall, pipe, boot, spawn, thread create + join hold; syscall and pipe pre-declared faster by the cheaper `mask_user`; boot pays the larger table fill (linear map in 1 GiB blocks: a few entries per GiB of RAM). Keeps: 60c's invariants (no kernel mapping writable and executable, through any alias); `unsafe` only in `arch` and the board; a user mapping never global and never reaching the kernel half. |
| 37a | Kernel virtual areas: guarded stacks, page-by-page tables | A stack area in the kernel half: each kernel stack (a task's, every core's idle and IRQ path, core 0's boot stack) is 16 KiB of frames mapped page by page into the lower half of a 32 KiB-aligned slot whose upper 16 KiB stays unmapped, the guard of the stack above it. Stacks no longer need contiguous frames, and neither do step 31's handle tables and multi-page pipe buffers, which move to a second area mapped page by page: their fragmentation `ENOMEM` (a named cap in phase 5) goes. Overflow: a stack overflow can only fault at EL1, so only the vectors for exceptions taken from EL1 check for it (Linux's test: SP with bit 14 set means it left its stack for the guard below; `add`/`sub`/`tbnz`, no register spilled) and switch to a per-core overflow stack that prints `panic: kernel stack overflow` with the task and the faulting address; the EL0 vectors (every syscall, every user IRQ) start at an empty stack's top and run no check. Freed task stacks go to a per-core cache of two still-mapped slots (their frames, two stacks per core, are held out of the root group's budget at boot like `CACHE_HELD`, so a refunded stack never leaves a budget headroom the allocator cannot back; reuse charges the next owner), so a thread create + join maps and flushes nothing in the common case; past the cache a slot's pages are unmapped with `tlbi vaae1is` per page. e2e `test=kstack`: a kernel task recursing past its stack prints the overflow panic naming it (from the overflow stack, so the report itself does not fault); a secondary core's idle stack overflow does the same (`-smp 4`); with the frame allocator fragmented by a fixture so that no two adjacent frames are free, a thread starts, a handle table grows past 8 pages and a 64 KiB pipe is created; `assert_no_leak`. Benchmarks: syscall, pipe, yield hold (EL0 entries unchanged, instruction counts checked under TCG `-icount`); thread create + join and spawn hold (the stack cache); boot holds. Keeps: every kernel stack has a guard; the overflow report never runs on the overflowed stack; `unsafe` only in `arch` and the board. |
| 38 | KASLR | The kernel is linked position-independent (`-C relocation-model=pie`, `lld --pie`, both stable) and `arch`'s boot code applies its `R_AARCH64_RELATIVE` relocations before any absolute address is used. Seed: `/chosen/kaslr-seed` (8 bytes, written by QEMU `virt` every boot unless `dtb-randomness=off`; the net stack keeps `rng-seed`), else FEAT_RNG's `RNDR` where present, else none: the fixed base and `kaslr: off (no seed)`. Randomized: the image's slot (2 MiB-aligned, so its block mappings stay, in a 128 GiB window: 16 bits), the stack area's and the device area's bases (2 MiB-aligned in the remaining kernel VA); the linear map fills its half and stays fixed (named). VBAR_EL1 points at a fixed-VA vector page whose entries load the randomized handler's address and branch to it, so v3a (A72 before r1p0) reads nothing secret (phase 10 Decided). `TCR_EL1.E0PD1` is set where ID_AA64MMFR2_EL1 reports E0PD (EL0 accesses to the kernel half fault in constant time), and the `spec:` line reports `kaslr: on` or `kaslr: weak (no E0PD)`; whether a CPU without E0PD pays for KPTI is the user's call with this step's numbers (Notes). e2e `test=kaslr`: two boots print different `kaslr: image <va>` bases and both run every scenario's smoke set; `-M virt,gic-version=3,dtb-randomness=off` boots at the fixed base with `kaslr: off (no seed)`; a panic and a fault report print offsets from the image base so they stay readable. ## Decided

- **Fault path under the process lock, no per-region locks** (coordinator, 2026-10-07): step 33. The frame is taken and zeroed before the lock, so the lock covers a table walk and a store; threads of one process faulting at once serialize only that. Linux needed per-VMA locks because its `mmap_lock` covered the whole fault (merged in 6.4, then weeks of crash fixes for VMA merging races: LWN 937943, "Stabilizing per-VMA locking", 2023). Per-region locks come only if 33's `bench-smp` fault mode shows the process lock contending.
- **Regions are a sorted `Vec` per process, binary-searched** (coordinator): step 33. O(log n) lookup, contiguous memory; Linux's maple tree (6.1) serves address spaces with tens of thousands of VMAs and RCU readers, which MogOs does not have.
- **TLB maintenance takes the narrowest correct form** (coordinator): steps 33-37, from Linux v6.18 `arch/arm64/include/asm/tlbflush.h` (read 2026-10-07): invalid to valid needs no TLBI ("invalid to valid transition requires no flush"); a changed leaf is `tlbi vale1is` per page between `dsb ishst` and `dsb ish`; a freed table is `vae1is` (walk caches too); past 512 pages one `aside1is` (`MAX_DVM_OPS = PTRS_PER_PTE`). A permission upgrade (CoW reuse, a shared page's first write) drops only this core's entry, and another core's stale read-only entry takes one spurious fault (Linux v6.18 `arch/arm64/mm/fault.c`, `__ptep_set_access_flags_anysz`: "Remote stale entries may still cause page faults", `TLBF_NOBROADCAST`). A CoW break changes the output address, so it is break-before-make (Arm DDI 0487, "Using break-before-make when updating translation table entries"; section number unverified here, checked in 34's plan review). That a faulting entry is never held in a TLB, which the first rule rests on, is per the Linux comment; the Arm ARM rule's ID is unverified. Fork pays one `aside1is` on the parent after its writable pages turn read-only, Linux's `dup_mmap` form (unverified this session). AArch64 broadcasts all of these, so no IPI (phase 5 step 25a).
- **ASIDs stay the process index** (coordinator): steps 33-38. No generation allocator (Linux v6.18 `arch/arm64/mm/context.c`) while live processes fit the ASID width (phase 5 step 31's named cap); TTBR1 entries are global, so the kernel never spends an ASID.
- **Lazy by default, `POPULATE` on request, no zero page, no anonymous fault-around** (coordinator): steps 33, 33a. A caller that touches every page asks for today's eager cost and loses nothing; a sparse caller pays per touched page. A shared zero page would add a second fault to the common write-after-malloc pattern, and anonymous fault-around zeroes pages that may never be touched; each is revisited only with a benchmark.
- **Page cache: per-file radix tree, S3-FIFO eviction** (coordinator): step 35. A per-file index (Linux's per-`address_space` radix tree, now XArray) makes truncate, unlink and per-file `msync` walk one file's pages in order, where a global hash (the survey's first sketch; Linux 2.4's page hash) scans or rehashes. S3-FIFO (Yang et al., "FIFO Queues are All You Need for Cache Eviction", SOSP 2023): FIFO queues, a hit is one relaxed bit store with no list move, and the small queue plus ghost queue resist scans. SIEVE (Zhang et al., NSDI 2024) is simpler but keeps no ghost and its authors call it not scan-resistant on some workloads (SIEVE site, "SIEVE is simpler than LRU", read 2026-10-07); MGLRU only if a benchmark asks.
- **The cache's cap bounds only what cannot be dropped** (coordinator, the reading of ROADMAP's "global cap" this doc takes; open question below): step 35. Clean pages may use any frame no budget has materialized and are given back on demand, so the cache is the slack (D2); dirty and in-flight pages are held under `CACHE_HELD`, reserved from RAM at boot outside every budget. Mapped file pages are charged to their mappers and pinned while mapped, so reclaim needs no reverse map; a page mapped by two processes is charged to both (named).
- **`write` stays write-through; no writeback task in this phase** (coordinator): steps 35-36. One copy for `read`, `write` and mappings without a dirty-page writer; shared writable mappings are the only dirty pages, written at `msync`, `sync`, `unmap` and exit. A writeback task with a per-device dirty bound waits for phase 7 step 42's async block path, where it can overlap I/O.
- **File fault-around maps up to 64 KiB of already-cached pages** (coordinator): step 36. Linux's `fault_around_bytes` default is 64 KiB (`mm/memory.c`; unverified this session); no I/O is started by it.
- **Fork copies page tables eagerly, anonymous and image regions only** (coordinator): step 34. File regions refault instead of being copied, as Linux skips copying PTEs a VMA can refault. On-demand-fork (Zhao, Gong and Fonseca, EuroSys 2021: page tables shared CoW, 65x faster than fork for 1 GiB processes) waits until 34's 32 MiB fork row shows the table copy dominating. The child pays its whole view up front, so a fork fails cleanly instead of overcommitting (Baumann et al., "A fork() in the road", HotOS 2019; ROADMAP Decided).
- **39-bit VA in both halves** (coordinator): step 37. Three-level walks keep every TLB miss one level shorter than 48-bit's four; 512 GiB of user VA and a 256 GiB linear map are named caps, above anything QEMU `virt` under hvf gives this host.
- **Kernel stack overflow is checked only on exceptions taken from EL1; freed stacks are cached** (coordinator): step 37a. Linux runs its `VMAP_STACK` test in every `kernel_ventry` (Linux v6.18 `arch/arm64/kernel/entry.S`: "Task and IRQ stacks are aligned so that SP & (1 << THREAD_SHIFT) should always be zero"); an entry from EL0 starts at the top of an empty stack and cannot overflow there, so the syscall path pays nothing. The two-stack per-core cache is Linux's `NR_CACHED_STACKS` (`kernel/fork.c`; unverified this session).
- **KASLR seed and granularity** (coordinator): step 38. `kaslr-seed` from the DT, else `RNDR`, as Linux v6.18 `arch/arm64/kernel/pi/kaslr_early.c`; QEMU 9.2.1 `hw/arm/virt.c` `create_randomness` writes an 8-byte `kaslr-seed` and a 32-byte `rng-seed` into `/chosen` under `dtb-randomness`. A 2 MiB-aligned image offset keeps the block mappings (Linux v6.18 `pi/map_kernel.c`: `kaslr_seed & ~(MIN_KIMG_ALIGN - 1)`). Linux enables KPTI with KASLR on a CPU without E0PD (`kaslr_requires_kpti`, same file), since TLB timing of EL0 probes into the kernel half defeats KASLR there; E0PD (ARMv8.5) makes those probes fault in constant time.
